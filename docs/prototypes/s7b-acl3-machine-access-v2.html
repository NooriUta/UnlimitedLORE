Тот же блок «Доступ», что в v1, но на условных данных в масштабе, близком к нашему. 10 наших проектов, в каждом 10–12 участников; всего людей 50+. У человека 1–2 harness, на каждый harness проекта — 2 машины. Данные сгенерированы с фиксированным зерном, поэтому при обновлении страницы они те же. Проверяем, где раскладка v1 перестаёт работать.

Как читать

  1. 1На таком объёме список машин нужен отдельной колонкой: поиск, фильтры по проекту и harness, группировка по владельцу или по проекту. В v1 машина была одна, и списка не было.
  2. 2Таблица допусков разбита на группы по проектам машины, группы сворачиваются. Есть поиск по людям. В группе показаны первые 8 человек, остальные — по кнопке «ещё N», как в лентах. Если в допуске больше трёх проектов, показываются три чипа и «+N».
  3. 3Человека выбирают через поле с поиском, а не через выпадающий список из 50+ имён. Сверху стоят участники проектов этой машины, ниже — все остальные с пометкой «не в проектах машины». Можно допустить сразу всю команду проекта, тогда в «что изменится» будет N строк.
  4. 4Перед применением показано, что изменится, а после применения есть «Отменить». Всё как в v1.
  5. 5Вкладка «Люди» отвечает на обратный вопрос: к каким машинам допущен человек. Это нужно, когда человек уходит (S7B-20): сразу видно, что у него снимать.
  6. 6Матрица показывает один проект целиком: строки — люди, столбцы — машины, на которых есть этот проект. По ней видно, у кого из команды нет доступа ни к одной машине.
