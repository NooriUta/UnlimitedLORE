Единый workflow для любой работы

SPRINT_LORE_WORK_ANY_KIND/WK-05 · правила decision:D-2026-LORE-UNIFIED-WORKFLOW-CORE и decision:D-2026-LORE-DONE-NEEDS-EVIDENCE · спека spec:SPEC-LORE-WORK-ANY-KIND · ADR-LORE-044

□ только прототип — в приложении ничего не меняется примеры — живые задачи LORE на 14.11.2026 тёмная amber Seiðr · токены
Что на утверждение. Восемь статусов ядра и переходы между ними; доказательство «сделано» для каждого вида работы; как статус, стадия и доказательство выглядят в паспорте задачи и в окне смены статуса. Отдельно — четыре развилки в конце страницы: спека их не решает.

1 · Восемь статусов ядра

Один словарь для спринтов и задач всех продуктов. Старые значения остаются синонимами, поэтому мигрировать данные не нужно (строка «было» на карточке).

waiting ≠ blocked. При waiting своя часть сделана, ход за внешней стороной. При blocked двигаться не можем мы сами.
failed ≠ cancelled. failed — известный отрицательный исход (отказали, проиграли, просрочили), он нужен в воронке. cancelled — решили не делать.

done ставится только из review. Прямого перехода active → done нет: «сделано» без приёмки и есть то, что 4–5 ноября дало 45 закрытий за два дня.

2 · Что считается доказательством

3 · Паспорт задачи и смена статуса

Выберите пример. Слева — паспорт, справа — окно смены статуса: нажмите статус в блоке «Можно перевести в». Роль «агент / человек» переключает, кто нажимает. Агент не ставит done никогда (правило владелицы 13.11.2026).

4 · Развилки — нужен ответ владелицы

А. Где живёт UAT. Спека знает восемь статусов; правило 13.11 добавило путь ready_for_deploy → агент проверяет на стенде → uat → done только человеком. Предложение: uat — стадия внутри review (stand_check → uat), а не девятый статус. Ядро остаётся восьмёркой, а приёмка человеком видна стадией.
Б. Два вида работы, которых нет в спеке. В LORE есть задачи ops и research/analytics (PL-14, RM-A4). Предложение: ops — доказательство «замер после правки» (прогоны, лог, проба) плюс PR, если менялся код; исследование — запись LORE с выводом (док, спека или решение), а не файл в рабочем дереве.
В. Доказательство на уровне задачи или спринта. Спека вешает evidence на оба. Предложение: у задачи — обязательно; у спринта — производное: сколько done задач его подтверждено (как «готово x/y»), своего поля нет.
Г. Старые done без доказательства. Таких done в корпусе сотни, RM-A4 из примеров — один из них. Предложение: задним числом не перекрашивать; в аналитике скорости и портфеля помечать «без доказательства» и считать отдельно. Разметку решаете вы (как MT-02).
