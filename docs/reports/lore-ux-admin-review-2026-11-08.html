Админка LORE: разбор и прототип v3

08.11.2026 · разбор кода src/components/lore/admin/ (состояние на 07.11) · прототип docs/prototypes/ux-admin-v3.html · данные прототипа: снимок LORE через MCP query_slice (агенты, проекты, 121 значение словарей, теги, участники UnlimitedLORE) и явно помеченное «демо» · принципы: [[lore_ux_redesign_principles_2026_11]], пп. 24–39
Коротко. Текущая админка уже сгруппирована по риску, и счётчики в ней честные. Но для рискованной зоны в ней нет трёх вещей, которых требуют принципы: журнала (кто, что, когда; человек или агент), страницы записи (боковая карточка есть только у людей) и подтверждения с диффом и «Отменить» (admin выдаётся и секрет ротируется двумя кликами). Поиск и фильтры списков в URL не хранятся, а при смене вкладки в адресе остаются ?doc= ?dict= ?roles=. Прототип v3 закрывает всё это и не теряет ни одной функции: ниже инвентаризация, где у каждой функции есть место в v3.

2. Что меняет прототип v3

  • Админка — отдельное приложение в переключателе сверху (его видит только admin) и пункт «Админка» в меню аватара. Там же, отдельно, «Личные настройки»: личное ≠ админка.
  • Боковая панель по смыслу и риску: Обзор · Доступ (высокий риск) · Справочники · Правила CLAUDE · MCP · Система · Журнал. Новые разделы: Сводка, Отказы доступа (вынесены из «Настроек»), Здоровье, Флаги, Версия, Журнал. На телефоне — строка «где я» с выпадающим списком.
  • Полоса «Система» на всех экранах: auth, KC, права агентов, роль, версия. Причина раскрывается по нажатию на чип — на телефоне наведения нет.
  • Один механизм для всех списков: [Фильтр][Группировка][Порядок] + поиск + строка «Показано N из M · фильтр · группировка · порядок · Сбросить всё». Всё состояние в URL (?s= &id= &t= &q= &f= &g= &o=); при смене раздела оно сбрасывается по одному правилу. Старые ссылки ?tab=…&user=/doc=/dict=/roles= нормализуются, на неизвестные выводится сообщение (вместо молчаливого перехода в «Словари»).
  • Страница записи у человека, агента, значения словаря, проекта, правила и настройки: шапка, строка-вердикт (например, «агент · профиль full · владелец omiloreadmin · последнее действие 2 мин · пишет: … · права не подтверждены бэкендом»), вкладки Обзор / Права / Участники / Дифф / Журнал. Правая колонка свойств по умолчанию скрыта, открывается «ушком», выбор запоминается.
  • Правка: изменённые поля подсвечены, внизу липкая полоса «изменён · Сбросить / Сохранить». Сохранение создаёт новую версию SCD2.
  • Рискованные действия: дифф «было → станет», ввод логина, кода или учётки, пометка «можно отменить» или «необратимо» (ротация секрета). После действия — уведомление с «Отменить» (10 с, aria-live) и запись в журнал.
  • Журнал — общий и у каждой записи: кто (бейдж «человек / агент»), что, над чем, когда. Фильтры по группе и исполнителю; у каждого блока ссылка «журнал раздела».
  • Честные состояния: ошибка — в шапке блока, с причиной и «Повторить»; пустота — «пусто (проверено)». Сценарии «KC 403», «KC недоступен», «слайсы упали» включаются кнопкой «Прототип: сценарий». Здоровье MCP: «не смогли проверить» вместо подмены. Теги: «40 из 500 — обрезано». Правила CLAUDE: предупреждение «слайс отдал 1 из 10».
  • Качество данных — фасетами фильтра: «сырой hex», «эмодзи в подписи», «без цвета», «неопознанные ключи», «агент молчит > суток».
  • Проверено Playwright в Edge: 28 адресов × 1440/800/412 — 0 ошибок страницы, горизонтального переполнения нет; axe color-contrast — 0 нарушений в тёмной и светлой теме (положительный контроль: на Сводке axe проверил 97 узлов). Отдельно прогнан сценарий «выдать роль → ввод логина → уведомление с „Отменить“» и фильтр агентов через меню.

4. Открытые вопросы к владелице

  1. Телефон: лента (вариант A, сейчас в коде) или выпадающий список (B, в прототипе)? Рекомендация: B — 11 и больше разделов в ленте не читаются.
  2. Заводить журнал админ-операций на бэкенде? Без него «Отменить позже» не работает, а вкладка «Журнал» пустая. Рекомендация: да — для рискованной зоны это блокер (AL-20/AL-43).
  3. Ввод подтверждения — для всех рискованных действий или только для необратимых? В прототипе он требуется на всё в «Доступе» и на канон-словари — это строже, чем сейчас.
  4. Учётки KC без агента — отдельный экран «Учётки» в «Доступе» или только свойство агента? В прототипе отдельной таблицы нет; функции A-13/A-14 нужно вернуть до внедрения.
  5. Слайс docs kind=claude-rules (через MCP — 1 из 10): заводить задачу на проверку скоупа и пометку «скрыто скоупом»? Пока это гипотеза.
  6. Данные: удалить app_setting «ффф» и перевести 6 словарей с hex и эмодзи на токены отдельной задачей?
  7. Слияние тегов прямо из админки (сейчас его делает только агент через MCP) — нужно?
Записей в LORE не делалось — так было в брифе. В прототипе демо-значения помечены пунктирным «демо», реальные — зелёным «LORE».
