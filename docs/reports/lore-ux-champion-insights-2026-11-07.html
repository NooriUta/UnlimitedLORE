Как референсы освобождают место для текста — и что взять LORE

07.11.2026 · Источники: документация и changelog Linear, Plane, OpenProject, Readwise Reader, Backstage, Obsidian, GitHub, Atlassian; W3C WCAG 2.1; Baymard; webtypography.net (Bringhurst). Пометка UNCONFIRMED — не удалось подтвердить по официальной странице.
  • Главный приём у всех один: боковые панели сворачиваются одной клавишей, а контекст (где я, какой это элемент, что рядом) остаётся тонкой строкой — хлебными крошками, счётчиком, полоской ToC. Linear, Confluence и Readwise Reader используют клавиши [ / ].
  • Ширина текста ограничена, а не растянута: 50–80 знаков в строке (WCAG 1.4.8 — не больше 80; Baymard — 50–75; Bringhurst — 66 знаков как идеал). Широкими делают только таблицы, диаграммы и код.
  • Один экран — три плотности: peek (боковая панель) → модальное окно → вся страница (Plane, Notion, OpenProject). Это одна и та же карточка, режим выбирается или запоминается.
  • Метаданные уходят из постоянной колонки: показываются в peek и в свёрнутой «шапке», панель свойств вызывается по требованию.
  • Для LORE: режим чтения по клавише + колонка ~72ch + плавающий ToC + J/K и «x / y» в шапке. Так тело задачи или ADR получает 70–80% ширины, а навигация не теряется.

1. Как освобождают место для длинного текста

Linear

  • Peek: Space открывает и закрывает предпросмотр задачи из списка или доски. Если держать Space, превью видно, пока клавиша зажата. J/K или стрелки переключают элемент, и превью идёт следом. В превью: описание, исполнитель, статус, приоритет, цикл, метки, оценка, даты. Открывается только с клавиатуры. В меню Cmd/Ctrl+K есть quick look по стрелке вправо. Источник: linear.app/docs/peek.
  • Левая навигация: полностью сворачивается клавишей [, кликом по границе или командой «Collapse». Так Linear предлагает «сфокусироваться на задаче» (changelog «collapsible sidebar»).
  • Шапка задачи с позицией «x / y» и переходом J/K к соседним задачам прямо из открытой задачи. UNCONFIRMED — по документации не нашёл, известно по продукту.
  • Клавиша для правой панели свойств (Cmd/Ctrl+I). UNCONFIRMED — сторонние справочники противоречат друг другу.
  • Свёрнутая история активности задачи (запись changelog 2025-04-03 «collapsed issue history»). UNCONFIRMED — нашёл только заголовок записи, сам текст не читал.

Notion

  • У каждого представления базы есть настройка «Open pages as»: side peek, center peek или full page. Side peek стоит по умолчанию, настройка общая для всех пользователей представления (release notes 20.07.2022).
  • Страница бывает двух ширин: по умолчанию узкая колонка, плюс переключатель «Full width» в меню ••• для каждой страницы. UNCONFIRMED по официальной справке (подтверждено сторонним гайдом).
  • Блок «/table of contents» строит оглавление по заголовкам. Плавающий ToC справа: в свёрнутом виде видны тонкие штрихи, полный список раскрывается при наведении. UNCONFIRMED — описание стороннее, и оно противоречиво.

Confluence

  • Боковая панель (дерево страниц) сворачивается клавишей [ или перетаскиванием края, выбор хранится в cookie браузера (Atlassian KB). В новой навигации (декабрь 2025) клавиша — Ctrl+[. Подтверждено только постом сообщества; доходит ли до всех инстансов — UNCONFIRMED.
  • Страница по умолчанию фиксированной ширины, есть переключатель на полную ширину. У изображений, таблиц и макросов своя ширина: fixed, wide или full. Данные из сообщества 2018–2020; текущее поведение Cloud — UNCONFIRMED.
  • Плавающий ToC: штатного нет (есть RFC-87 с целевым сроком 2025, вышел ли — UNCONFIRMED). Пока используют макрос в тексте или маркетплейс-приложения вроде Easy Heading.

Obsidian

  • Левая и правая панели сворачиваются стрелкой или командами «Toggle left/right sidebar». На мобильных панели свёрнуты по умолчанию и открываются свайпом. В правую панель можно перетащить заметку, чтобы держать её рядом (obsidian.md/help, Sidebar).
  • Настройка «Readable line length» ограничивает ширину текста. На форуме называют фиксированный предел около 700px; ширину меняют CSS-сниппетом, а для отдельной заметки — через cssclass. Плагины добавляют горячую клавишу и слайдер. Величина 700px — со слов пользователей форума.
  • Outline (оглавление) как вкладка в боковой панели, вкладки и стопки панелей. UNCONFIRMED — на просмотренной странице не описано.

GitHub / GitLab

  • Для любого отрендеренного Markdown-файла GitHub сам строит оглавление по заголовкам и открывает его кнопкой «Outline» в углу файла. У заголовков есть якорные ссылки. Содержимое README сверх 500 KiB обрезается (docs.github.com, About READMEs).
  • Широкий режим и «zen» в диффах PR, аналоги в GitLab. UNCONFIRMED — не проверял.

Jira (новый вид задачи)

  • Правая панель полей стала регулируемой по ширине в мае 2022 (ответ сотрудника Atlassian в сообществе).
  • Полностью свернуть панель полей и отдать место описанию просят давно (JRACLOUD-76766). Штатной возможности не нашёл, пользователи обходятся консольными хаками. Текущий статус — UNCONFIRMED.
  • В июне 2026 в списках появилась «preview panel» шириной около половины экрана. Пользователи жалуются, что пропал переключатель List/Detail. Это отзывы пользователей, не документация.

Readwise Reader и режимы чтения

  • [ и ] скрывают и показывают левую и правую панели. Можно задать «Hide side panels by default in reading view», то есть видимость панелей по умолчанию при входе в чтение (docs.readwise.io, Navigation FAQ).
  • Ширина строки: по умолчанию medium, меняется клавишами Shift+, / Shift+.. Межстрочный интервал по умолчанию 1.4, меняется клавишами Shift+: / Shift+" (Appearance FAQ).
  • Medium, Substack, Safari Reader: узкая колонка около 680–700px и крупный кегль. UNCONFIRMED — точные значения не проверял.

Backstage TechDocs

  • Раскладка в три зоны: слева навигация, в центре текст, справа ToC. У аддонов есть места: PrimarySidebar (над навигацией), SecondarySidebar (над ToC), Header, Subheader и Content.
  • Аддон ExpandableNavigation сворачивает и разворачивает всю навигацию и запоминает выбор для всех сайтов документации. TextSize меняет кегль слайдером и хранит его в localStorage. ReportIssue: выделил текст — и сразу завёл issue. LightBox открывает картинки поверх страницы (backstage.io, TechDocs Addons).

Plane / OpenProject

  • Plane: рабочий элемент открывается в peek overview, отображение на выбор: side peek (по умолчанию), modal или full screen. Часть функций видна только в полноэкранном виде, и пользователи этого не замечали (docs.plane.so, GitHub discussion #3386).
  • OpenProject: кнопка «i» включает split screen рядом с таблицей, двойной клик или иконка в шапке открывает full screen. Вкладка Activity с комментариями и изменениями есть в обоих режимах, её можно фильтровать и менять порядок (docs.openproject.org).

2. Типографика длинного чтения

  • Длина строки. WCAG 2.1, SC 1.4.8 (AAA): «ширина не более 80 знаков (40 для CJK)». Baymard: оптимально 50–75 знаков, 80 как верхний предел. Bringhurst: «строка в 66 знаков, считая пробелы, считается идеальной», для нескольких колонок 40–50. Для веба советуют задавать ширину в em или ch, чтобы мера масштабировалась вместе с кеглем (webtypography.net 2.1.2: 33em ≈ 66 знаков). Оговорка: Viget приводит исследование, где экранное чтение было быстрее на 95 знаках. Скорость при этом не равна удобству, поэтому опора — WCAG.
  • Межстрочный интервал. WCAG 1.4.8: не меньше 1.5 внутри абзаца, абзацный отступ не меньше 1.5 межстрочного. Readwise по умолчанию ставит 1.4. Для тела в LORE: 1.55–1.6.
  • Оглавление. Строится автоматически по заголовкам (GitHub, Notion, TechDocs). В свёрнутом виде видны тонкие штрихи, по hover раскрывается полный список (Notion) (UNC).
  • Липкая шапка. Когда панели скрыты, контекст держит одна строка: хлебные крошки, код и заголовок элемента, статус, «x / y». Отдельной цитаты по sticky breadcrumbs не нашёл, это вывод из паттернов выше. UNCONFIRMED как исследование.
  • Постепенное раскрытие метаданных. Peek в Linear показывает ровно ключевые поля. Остальное в панели по запросу или свёрнутой секции.

3. Инсайты от референсов

Здесь аналитика, не пересказ фич. Фактическая опора — в разделе 1, остальное — интерпретация.

Linear

  • Список никогда не теряется: из открытой задачи доступны J/K и позиция «x / y», поэтому чтение не стоит навигации. (x / y — UNC)
  • Peek создан для решения «открывать или нет», а не для чтения. Он по клавише и временный (зажатый Space), и поэтому не съедает место постоянно.
  • Фокус стоит одну клавишу: [ убирает навигацию, а не прячет её где-то в настройках.
  • Для LORE: превью в боковой панели — для сортировки списка; читать — на всю ширину, с J/K по тому же списку.

Notion

  • Способ открытия — свойство представления, а не пользователя: команда договаривается, где «читать», а где «сортировать».
  • Узкая колонка по умолчанию, широкая — осознанным выбором. Читаемость встроена изначально, её не нужно настраивать.
  • Для LORE: у слайса или вкладки — режим открытия (peek/full) по умолчанию; у документа — флаг «широкий», остальные узкие.

Jira / Confluence

  • Антипример Jira: панель полей годами нельзя скрыть (JRACLOUD-76766). Постоянная колонка метаданных — главный враг описания задачи.
  • У Confluence ширина — свойство блока: текст фиксированный, таблица и диаграмма широкие. Один документ — две меры.
  • Для LORE: не повторять «вечную правую панель»; mermaid и таблицы выводить шире колонки текста.

Obsidian

  • Всё вокруг текста — вкладки панелей (outline, бэклинки, файлы), их можно переставить или убрать. Центр всегда принадлежит заметке.
  • Ограничение ширины включено как настройка, а не зашито. Пользователи сразу просят крутилку, значит одной цифры мало.
  • Для LORE: читаемая ширина по умолчанию и ручка «уже/шире», запоминаемая для пользователя.

Redmine

  • Задача — это страница: описание сверху, журнал изменений под ним. Без панелей, зато с полной шириной и прямым URL. Скучно, но текст читается.
  • Для LORE: полностраничный вид задачи или ADR как первичный режим для чтения, а не «развёрнутая панель».

Plane / OpenProject

  • Три режима одной карточки снимают спор «панель или страница», но функции не должны прятаться в одном из них: пользователи Plane не находили возможности full screen.
  • Активность доступна в обоих режимах (OpenProject): история не привязана к размеру окна.
  • Для LORE: в peek и full одинаковый набор действий; в peek они свёрнуты, но не отсутствуют.

Backstage TechDocs

  • Документация — главный контент, а каталог только рамка: навигация сворачивается целиком, выбор запоминается для всех сайтов.
  • У чтения есть «слоты» для инструментов (кегль, «сообщить о проблеме» по выделенному тексту) — улучшение не ломает разметку.
  • Для LORE: «выдели текст → задача или вопрос» прямо из тела ADR или спеки.

Logseq / Tana

  • Блок адресуем: на абзац можно сослаться, его можно раскрыть или свернуть. Длинный текст читается сворачиванием, а не прокруткой.
  • Боковая панель там — стопка открытых ссылок, а не свойства: контекст — то, что я сейчас читаю рядом. (по опыту продукта, UNC)
  • Для LORE: сворачиваемые секции по заголовкам в MartProse; ссылку на связанный ADR открывать рядом, а не вместо.

SonarQube

  • Один вердикт сверху (прошёл или не прошёл гейт), подробности ниже. Человек сначала узнаёт ответ, потом причину.
  • Для LORE: в шапке задачи, ADR или релиза одна строка состояния (статус, блокеры, гейт); тело — ниже, без колонки цифр сбоку.

Port / Cortex

  • Карточка сущности собирается из виджетов по типу: у сервиса и у команды разные «паспорта», а не одна форма.
  • Scorecard как короткий вывод «что не так» вместо таблицы полей.
  • Для LORE: паспорт по типу (задача, ADR, спека) с минимальным набором полей в шапке; остальное по запросу.

Productboard

  • Фича связана с «голосом пользователя»: рядом с описанием видно, почему её делают.
  • Для LORE: в шапке задачи — компактная связь с болью или решением (одна строка), а не отдельная вкладка.

Grafana / Atlan

  • Grafana: у панели есть режим просмотра на весь экран и обратно. Плотная сетка не мешает изучить одно.
  • Atlan: у ассета есть README и lineage, а поля свёрнуты в профиль. Описание — первоклассный объект.
  • Для LORE: «развернуть блок» (mermaid, таблицу) на весь экран одной кнопкой.

Linear Releases

  • Релиз — лента сгруппированных изменений с короткими пояснениями, а не таблица задач.
  • Для LORE: релиз читается как документ (разделы и буллеты), а связанные задачи видны свёрнутым списком.

Langfuse

  • Трейс — дерево слева и детали узла справа; длинные вход и выход сворачиваются и раскрываются, JSON и текст переключаются.
  • Для LORE: в длинных телах сворачивать громоздкие блоки (код, логи) по умолчанию, раскрывать по клику.

Sourcegraph

  • Чтение кода с панелью ссылок и определений по требованию: контекст подтягивается к тексту, а не висит постоянно.
  • Для LORE: hover или peek по ссылке на сущность (SPRINT/код, ADR) прямо в теле, без перехода.

4. Что из этого предлагаю для LORE

  1. Режим чтения по клавише ([ — навигация, ] — панель свойств; можно оба сразу). Выбор хранится в URL и localStorage. Опора: Linear, Confluence, Readwise.
  2. Липкая шапка-контекст в одну строку: крошки, код, заголовок, статус-chip, «x / y» и J/K по текущему списку. Список можно закрыть, а позиция в нём остаётся. Опора: Linear.
  3. Колонка текста ~72ch (max-width: 72ch, line-height 1.55–1.6). Mermaid, таблицы и код выходят шире (breakout). Опора: WCAG 1.4.8, Bringhurst, Confluence.
  4. Плавающий ToC по заголовкам MartProse справа: в покое тонкие штрихи, по hover — список, подсветка текущей секции. Опора: Notion, GitHub Outline, TechDocs.
  5. Одна карточка — три плотности: peek (сортировка списка) → full page (чтение). Один набор действий в обоих режимах, режим по умолчанию задаётся на вкладке. Опора: Plane, Notion, OpenProject.
  6. Метаданные — chip-строкой в шапке вместо постоянной правой колонки; полная панель — по ]. Опора: антипример Jira, peek Linear.
  7. Ручка «уже/шире» и кегль на стороне читателя, запоминается. Опора: Readwise, TechDocs TextSize, Obsidian.
  8. Развернуть блок на весь экран (mermaid, таблица) и свернуть громоздкие блоки по умолчанию. Опора: Grafana, Langfuse, TechDocs LightBox.
