# LORE — выпуски за три недели (01–22.11.2026), главное

За период: **v1.13.1 → v1.19.0** (готовится), 36 тегов, из них мажорных пять: 1.14, 1.15, 1.16, 1.17, 1.18. Главное в трёх словах: интерфейс v2 стал основным, схема базы собирается из модели, а LORE научилась ставиться у другого человека.

## Установка у другого человека (главное за период)

- **Из образа вынуты «гвозди»**: адреса LORE, Keycloak и git-хоста больше не впекаются при сборке — читаются при запуске. Проверка в сборке ищет наши домены, области, имена машин и организаций в образе и в каждом файле пакета и не даёт им вернуться.
- **Пакет установки стал настоящим пакетом**: `install.sh` для Linux, `install.ps1` для Windows (один и тот же сценарий, разный вход), compose, `.env.example`, README и инструмент переноса. Вложения выпуска: пакет, пакет в zip, исходники, подписи.
- **Один файл с окном** — установщик, окно, перенос и пакет внутри; Node внутри, доустанавливать нечего.
- **MCP ставится вместе со стеком** — агент подключается по адресу установки, без локальной сборки.
- **miniLORE по выбору** — сервер мобильного монитора ставится тем же установщиком, базы заводит сам.
- **Keycloak честно спрашивается**: своя область, свои клиенты, свои секреты — тогда LORE не делает ни одной записи в чужой Keycloak, только проверяет, что по паре выдаётся токен с нужной ролью.
- **Раздел «Рекомендации»** в README и в окне: HTTPS-прокси, внутреннее имя на внутренний адрес, бэкап с проверкой восстановления, свой Keycloak, зеркало образов — в форме «что будет без этого».

## Модель и данные

- **Схема собирается из модели**, а не наращивается миграциями; данные переносятся одним проходом с проверкой, остаток не теряется, а попадает в «остаток» с причиной.
- **Связи помнят время**: `valid_from`/`valid_to`, снятая связь закрывается, а не исчезает.
- **Репозитории и организации — свои записи** с паспортами и ролями (основной, компонент, зеркало, используется); заводить можно из клиента, а не раз в выпуск.
- **Контракт экрана-списка в модели**: у 26 типов описано, какой срез и какие поля показывать — клиенты строят списки по модели, а не по копии в своём коде.
- **У модели есть номер** (`model:1`), и правка схемы обязана его поднять.
- **Поля проектов и продуктов описаны моделью целиком**, паритет сторожит проверка в сборке.

## Интерфейс v2

- **Паспорт записи** для всех видов, «Ждём» и причина статуса у задачи, переход по ссылкам из тела.
- **Графики** — своей вкладкой «Аналитика», а не над содержимым: CFD, прогноз вехи, время цикла, WIP, возраст задач, блокировки, ритм релизов, действия агентов, отказы MCP.
- **Супертеги** — «#тег» с полями прямо в тексте и экран всех записей с тегом.
- **Люди и агенты по-человечески**: человек подписан именем из Keycloak, владелец агента — именем, а не опознавателем; внутренний код агента из списка убран.
- **Фильтр по продуктам** в шапке, а не по проектам: сервер сам раскрывает продукт в его проекты.
- **Лента новостей по столбцам**, многоточие в колонках (длинный текст не раздвигает таблицу).

## kit (общие части интерфейса)

- **Свой репозиторий** `AIDA/lorekit` со своей сборкой; LORE переносит его к себе целиком и помечает, из какого состояния. Следующий шаг — kit пакетом по версии.
- **Подключаемые языки**: словарь передаёт приложение, формы чисел — по правилам этого языка.
- **Живые кубики**: команда с подтверждением (отправлено → подтверждено → исполнено), регулятор и переключатель по факту, загрузка файла с прогрессом, короткий плеер записи.
- **Плитки показаний**: пять видов, искровая линия рвётся на пропуске, «оценка» помечена.
- **Схема модели** — отдельным кубиком.

## Агенты и доступ

- **Учётка на harness, роли по старшинству**: `lore-mcp-<роль>` у Claude Code, `lore-mcp-<роль>_<harness>` у остальных; выпустить роль выше главной нельзя — сервер отказывает до похода в Keycloak.
- **Секрет сразу в хранилище** при выпуске и смене; не настроено — сказано прямо.
- **Вкладка «Учётки»** в админке: что есть, когда менялся секрет, кнопки выпустить/сменить/выключить.
- **Сторож входов в базу под root**: первый вход «пользователь × источник» записывается, вход не из разрешённых источников помечается тревогой.

## Технологии

- Схема и перенос: ArcadeDB 26.11.1, модель `model:1`.
- Новые службы `lore-mcp` и `db-guard` — на `node:26-alpine`.
