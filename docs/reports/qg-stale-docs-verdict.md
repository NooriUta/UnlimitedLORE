# Формат вердикта сверки ADR и спек с кодом — черновик на согласование

Задача: SPRINT_QG_REBUILD/QG-STALE-DOCS, шаг 1. Статус: **черновик 0.1, 20.11.2026, ждёт согласования владелицы.** Кода нет.
Продолжает SPEC-QG-JOB-CONTRACT (рутина канала 2, суждение — LLM через `ModelRouter`, без инструментов).

## 1. Кратко

- На каждую сверку — одна запись вердикта: **документ × снимок кода** (SHA develop).
- Значение — одно из пяти: `current | future | partly_stale | stale | superseded`.
- К значению прикладываются уверенность 0..1, короткое рассуждение и **доказательства, которые можно перепроверить**: путь, строки и SHA, запись LORE или явный поиск «не нашлось» с положительным контролем.
- Вердикт по документу собирается из вердиктов по **утверждениям** (claim) — по разделам и решениям. Целый ADR редко устаревает весь сразу.
- Выход рутины — рекомендация на решение владелицы (`rec_*`), а не правка статуса документа. Метку «устарел» и «заменён» ставит только она.

## 2. Пять значений

| значение | когда ставится | чем отличается от соседа | предлагаемое действие |
|---|---|---|---|
| `current` | Утверждения документа подтверждены кодом этого SHA | — | оставить |
| `future` | Утверждений в коде нет, и документ **сам говорит**, что это план: статус `proposed`, раздел «порядок внедрения», открытая задача с JUSTIFIED_BY на документ | от `stale`: признак «план» есть в самом документе или в открытой задаче. Без признака отсутствие в коде — не «будущее» | оставить; следить за задачей |
| `partly_stale` | Часть утверждений `current`, часть `stale`. Часть может быть `future` | от `stale`: есть хотя бы одно подтверждённое утверждение | переписать устаревшие разделы |
| `stale` | Код ушёл в другую сторону **или** утверждаемого больше нет, и признака «план» нет. Замещающей записи нет | от `superseded`: никто не написал «вместо этого» | переписать или отменить — решает владелица |
| `superseded` | Есть **другая запись LORE**, которая решает тот же вопрос иначе: ребро SUPERSEDES **или** (уровень LLM) содержательное совпадение предмета с более новой записью, подтверждённое кодом | от `stale`: есть на что сослаться | пометить заменённым и завести ребро SUPERSEDES |

**Правило о пустоте.** «В коде не нашлось» само по себе не доказывает ни `stale`, ни `future`. Доказательство отсутствия обязано нести поисковый запрос и **положительный контроль** — тот же поиск находит заведомо существующее (правило из памяти проекта: «пустой ответ ≠ не найдено»). Нет контроля — у утверждения `not_checked`, и оно не голосует.

## 3. Запись вердикта

```json
{
  "doc": {"type": "spec", "id": "SPEC-QG-JOB-CONTRACT", "version": "0.1.0", "hist_valid_from": "2026-10-20T12:06:07Z"},
  "code": {"repo": "AIDA/UnlimitedLORE", "ref": "develop", "sha": "e24e1530"},
  "verdict": "partly_stale",
  "confidence": 0.8,
  "reasoning": "до 600 знаков: почему именно это значение, что перевесило",
  "claims": [
    {"where": "§3 пять концовок", "claim": "попытка пишется RUNNING до работы; зависшую закрывает надзиратель как ABORTED",
     "verdict": "current", "confidence": 0.95,
     "evidence": [{"kind": "code", "path": "backend/src/main/java/studio/seer/heimdall/lore/QgAttemptRunner.java", "lines": "46-48", "sha": "e24e1530", "quote": "sink.write(req(runId, … RUNNING …"}]}
  ],
  "replaced_by": null,
  "action": {"kind": "rewrite", "sections": ["§2 интерфейс"], "text": "что именно переписать"},
  "run": {"run_id": "qg-stale-docs_20261120T2130Z", "model": "Qwen3.5-122B-A10B", "input_hash": "sha256:…", "tokens": 41230}
}
```

Поля:

- `claims[].verdict` — `current | future | stale | superseded | not_checked`. «Частично» бывает только у документа целиком, не у утверждения.
- `evidence[].kind`:
  - `code` — путь, строки, SHA и цитата не длиннее 200 знаков;
  - `record` — запись LORE, которая подтверждает или заменяет: задача, решение, ADR;
  - `edge` — ребро SUPERSEDES, IMPLEMENTED_IN или JUSTIFIED_BY;
  - `absence` — запрос, область поиска и положительный контроль.
- `confidence` — уверенность модели в значении. Правила калибровки — §5. Меньше 0,6 — рекомендация уходит с пометкой «нужен взгляд человека», а не «пометить».
- `action.kind` — `keep | watch | rewrite | mark_stale | link_supersedes`. Это предложение, а не действие.
- `run.input_hash` — хэш входа: текст документа и выдержки кода. По нему проверяется детерминизм: тот же вход → тот же вердикт.

## 4. Сборка вердикта документа из утверждений

| утверждения (без `not_checked`) | вердикт документа |
|---|---|
| все `current` | `current` |
| все `future` | `future` |
| `current` и `future`, без `stale` | `current` с действием `watch` (план частично исполнен — это норма для спеки-предложения) |
| есть `stale` и есть `current` или `future` | `partly_stale` |
| все `stale` | `stale` |
| есть `superseded` и замещающая запись покрывает больше половины утверждений | `superseded` |
| все `not_checked` | вердикта нет: рекомендация «не смогли проверить» с причиной, **не** `current` |

## 5. Как модель рассуждает и где её держат

1. Механический уровень (уже есть, `qg-doc-links`, PR #1432) идёт первым: битые ссылки, снятые типы, рёбра SUPERSEDES. Если ребро SUPERSEDES есть — `superseded` ставится без LLM.
2. Код собирает выдержки детерминированно: идентификаторы, пути, имена классов и ключи конфигурации из текста документа → `git grep` по SHA. Модель получает документ и найденные выдержки **с путями**. Сама модель ничего не ищет (И-3).
3. Модель разбивает документ на утверждения и проверяет каждое по выдержкам. Признаки «плана» в тексте: статус `proposed`, «предложение», «порядок внедрения», «шаг N»; открытые задачи с JUSTIFIED_BY на документ даёт код.
4. Калибровка уверенности:
   - ≥ 0,9 — есть цитата кода, которая прямо подтверждает или опровергает;
   - 0,6–0,9 — подтверждение косвенное (имя есть, поведение не видно);
   - < 0,6 — только отсутствие с контролем или рассуждение без цитаты.
5. Детерминизм: `temperature=0`, неизменная инструкция в системной части (кэш), прогон эталона дважды → одинаковые `verdict` по всем документам.
6. Объём: локальная модель — 131 072 токена контекста, одна очередь, окно работы 21:00–08:00 МСК. Документ длиннее 60 тыс. токенов с выдержками режется по разделам, утверждения сводятся кодом.

## 6. Три примера на живых документах (develop e24e1530, 20.11.2026)

Сверены вручную тем же порядком, что предложен для рутины.

### 6.1 ADR-LORE-050 — `current`, уверенность 0,85

ADR от 10.11.2026, ACCEPTED: «[[», «@» и «#тип» открывают одно мини-окно; пометка `required: 'block' | 'warn'` в контракте kit.

| утверждение | вердикт | доказательство |
|---|---|---|
| три способа вызова | current 0,95 | `kit/src/content/refTrigger.ts:12` — `RefTriggerKind = 'brackets' \| 'at' \| 'hash'`; `kit/src/content/TipTapField.tsx:85` — `char: '@'` |
| пометка `required?: 'block' \| 'warn'` в контракте kit ↔ приложение | current 0,95 | `kit/src/core/contract.ts:65` — `required?:'block'\|'warn'` (D-2026-LORE-RECORD-FIELD-REQUIRED) |
| block — из схемы, warn — из проверок качества | current 0,8 | `kit/src/record/recordDoc.ts:303` — `required: 'block'` из `f.required`; `backend/.../LoreFieldRequirement.java:32` — `required_level — block \| warn` |
| карточка «новый»: сначала обязательные поля, отказ по block, предупреждение по warn | current 0,9 | `kit/src/content/RefPicker.tsx:60` — `warned: fields.filter(f => f.required === 'warn' …)`; `:174` — пометки «обязательно» и «желательно» |
| в чтении (MartProse) окно только показывает карточку | current 0,85 | `kit/src/content/MartProse.tsx:26,259` — `useRefPeek`, «[[ссылка]] в чтении → ссылка на паспорт записи» |
| гипотеза ADR: служба поиска годится для выпадающего списка | not_checked | замера в коде нет, это и не утверждение о коде |

**Рассуждение.** Все проверяемые утверждения подтверждены цитатами. Гипотеза из §5 ADR — не утверждение о коде, в сборку не идёт. Уверенность 0,85, а не 0,95: поведение «отказ до отправки» видно по коду, но живым прогоном не проверялось.
**Действие:** `keep`.

### 6.2 SPEC-QG-JOB-CONTRACT 0.1.0 — `partly_stale`, уверенность 0,8

Спека-предложение от 20.10.2026. Часть разделов исполнена, часть разошлась с кодом, часть ещё впереди.

| утверждение | вердикт | доказательство |
|---|---|---|
| §3: RUNNING пишется до работы; концовки — отработала, предусловие, исключение | current 0,95 | `QgAttemptRunner.java:46-72` (develop) |
| §3: зависшую закрывает надзиратель как ABORTED | current 0,95 | `QgSupervisorRoutine.java:21,31` |
| §7: выключена до `.enabled=true`; `.every` ISO-8601; перекрытие пишется флагом `overlap` | current 0,95 | `QgScheduler.java:33-36, 93, 113-125` |
| §2: интерфейс `check(QgContext ctx)`, `collect(QgContext ctx)`, `analystPrompt()` | **stale** 0,85 | `QgRoutine.java` (последняя правка 12b727bc, 20.10): `Precondition check()`, `List<RawFact> collect()` — без контекста; `analystPrompt` и `QgContext` по `backend/src/main` не находятся. Контроль: тот же поиск находит `QgRoutine` и `Precondition` |
| §2: инструкция аналитика — ресурс `backend/src/main/resources/qg/<name>.md`, без него отказ старта | future 0,7 | каталога `resources/qg/` нет; спека сама ставит аналитика на шаг 3 §8, а SPRINT_QG_REBUILD/QG-11 называет шаг 3 «впереди» |
| §4: `.max-usd`, `.max-output-tokens`, цена `lore.llm.price.<model>.*`, `price_unknown` | future 0,8 | на develop ключей нет; реализуется PR #1642 (SPRINT_QG_REBUILD/QG-15), причём ключ там назван `.max-tokens` (суммарно), а не `.max-output-tokens` — после влития это утверждение станет `stale` по имени ключа |
| §6: надзиратель ставит флаг `cache_broken` | future 0,6 | `cache_broken` по `backend/src/main` не находится; надзиратель есть, этой проверки в нём нет |

**Рассуждение.** Раздел, по которому исполнитель уже построен (§3, §7), подтверждён. Набросок интерфейса в §2 разошёлся с кодом: так спеку писали до реализации. Это не план, а неточность, поэтому `stale`. Бюджет и кэш — `future`: спека сама относит их к следующим шагам.
**Действие:** `rewrite` §2 (интерфейс по коду) и §4 (имя ключа после #1642).

### 6.3 ADR-QG-001 — `superseded` (предложение), уверенность 0,75

ADR от 30.06.2026, ACCEPTED, ребра SUPERSEDES нет — механический уровень этого **не видит**. Предмет тот же, что у ADR-LORE-053 (15.11.2026, ACCEPTED): как исполняется рутина QG и как пишется «не измерено».

| утверждение | вердикт | доказательство |
|---|---|---|
| §4: рутина исполняется Claude-промтом с MCP — читает `content_md`, сам выполняет проверки Bash и curl | superseded 0,85 | ADR-LORE-053-D1: «рутины QG исполняет наш сервер по расписанию; числа считает детерминированный код»; код — `QgScheduler.java`, `QgAttemptRunner.java` |
| §2: недоступный сервис → `value=-1, status=SKIP` | superseded 0,9 | ADR-LORE-053-D2: NOT_MEASURED с обязательной типизированной причиной; `LoreQgRunWriter.java:41-46, 85-93` — SKIP помечен «легаси-формой», без `not_measured_reason` запись отвергается |
| §1: запись через `lore_record_qg_run` с `metrics[]` | stale 0,8 | MCP-инструмент называется `qg_run_log` (`mcp-server/src/tools/loreWrite.ts:2116`); `lore_record_qg_run` в `mcp-server/src/tools` не находится. Форма `metrics[]` жива |
| §6: обязательные разделы рекомендации (Root Cause, Evidence…) | not_checked | правило о тексте рекомендации, в коде не проверяется |

**Рассуждение.** Два центральных решения ADR прямо заменены решениями ADR-LORE-053, и код следует новому. Это `superseded`, а не `stale`: есть на что сослаться. Уверенность 0,75: замену видно по содержанию, явной ссылки «вместо ADR-QG-001» в ADR-LORE-053 нет.
**Действие:** `link_supersedes` — предложить ребро ADR-LORE-053 → ADR-QG-001 SUPERSEDES. Решения ADR-QG-001-D2 и -D4 пометить заменёнными. Ставит владелица.
