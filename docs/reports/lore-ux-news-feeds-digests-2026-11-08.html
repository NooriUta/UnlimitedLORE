Ленты изменений и сводники метрик: как делают и куда встраивают

08.11.2026 · лёгкий ресёрч (≈40 мин) по запросу владелицы: «как RSS-ленту и сводник метрик изменений делают, куда встраивают» · проверено по документации: GitHub Pulse и Atom, Linear Pulse, GitLab VSA, Basecamp, Grafana · пометка по знанию продукта = не перепроверено в этом заходе · смежный разбор: lore-ux-news-analytics-objects-2026-11-08.html
Коротко
  • Лента и сводник — разные вещи. Лента — поток событий «кто что сделал», её читают в моменте. Сводник — свёртка за период с числами и дельтой к прошлому периоду, его читают по расписанию. Сильные продукты держат оба и связывают: из числа сводника можно провалиться в события ленты.
  • Главный приём против шума — свёртка. События группируют по дню, объекту и автору («Иван закрыл 5 задач в SPRINT_X» вместо пяти строк). Срочное идёт мимо свёртки отдельным уведомлением.
  • Персонализация держится на трёх механиках: непрочитанное с «прочитано до сюда», подписка на объекты и проекты, сохранённые фильтры как своя лента (Linear Pulse, Inoreader).
  • Встраивают в 5 мест: домашняя страница, вкладка «Активность» на странице объекта, inbox, письмо или пуш по расписанию, адрес RSS/Atom. Бот в чате и мобильная версия продолжают сводник.
  • Для LORE (решение владелицы: только лента, без уведомлений): свёртка по дню и периоду с метриками прямо в ленте, «прочитано до сюда», Atom-адрес на любой фильтр (подписка по запросу читателя, не рассылка), та же лента на страницах проекта и вехи и на стартовом экране телефона, метка «агент» с указанием, от чьего имени он действовал.

Как делают ленту

GitHub: лента активности, уведомления, Atom
  • Что показывают: на главной — ленту по подпискам (звёзды, follow). Отдельно — inbox уведомлений с причиной («упомянули», «назначили», «просили ревью») и фильтрами по причине и репо по знанию продукта.
  • Atom: у публичного репо есть releases.atom, tags.atom, commits.atom и commits/{branch}/{path}.atom, то есть лента по ветке и даже по одному файлу. Для issues и PR лент нет. Приватные репо без входа не отдаются.
  • Урок: скоуп ленты записан прямо в адресе (репо → ветка → путь), поэтому подписаться можно на любой срез.
Linear: Pulse и Inbox сводка в inbox и Inbox — не для LORE по решению владелицы
  • Pulse показывает не сырые события, а «апдейты» проектов и инициатив, которые пишут люди: статус (on track / at risk) и текст. Вкладка «For me» — подборка под пользователя. Сохранённые фильтры (автор, команда, проект, статус) работают как личные ленты.
  • Сводка в inbox: её пишет ИИ, приходит ежедневно или еженедельно к 7:00 по местному времени, ритм по умолчанию задаёт админ. Есть аудио-версия и мобильный клиент. По стороннему трекеру, запись начинается с итога в одно предложение.
  • Inbox — личные уведомления с действиями «прочитано», «отложить», «отписаться» по знанию продукта.
  • Урок: поток сырых событий и курируемые апдейты разделены. Один апдейт со статусом проекта ценнее сотни смен статусов задач.
Jira и Confluence: поток активности, гаджеты, письма
  • Activity Stream — гаджет для дашборда и вкладка на странице проекта или задачи. Фильтры: проект, пользователь, тип события. У потока есть RSS-адрес по знанию продукта.
  • Confluence — лента «недавно изменено» по пространству и письма-дайджесты «популярное за неделю» по знанию продукта.
  • Урок: лента как переносимый виджет: один и тот же поток с параметрами ставится на любой дашборд.
Basecamp: Activity и автоматические опросы
  • Activity — общая лента по всем проектам и отчёты: «что сделал человек», «что просрочено», Hilltop View (все Hill-чарты в одном месте). Чарты без обновлений больше 3 месяцев туда не попадают.
  • Automatic Check-ins — вопросы по расписанию («что сделал сегодня?»). Ответы собираются в одну ветку на странице проекта. Это замена стендапа: людей просят писать о сути, а не о кликах.
  • Hill Charts делят прогресс на «ещё разбираемся» и «уже делаем». Сдвиг точки на холме — тоже событие.
  • Урок: отсеивать устаревшее и спрашивать людей о сути.
Читалки RSS: Feedly, Inoreader, Readwise Reader
  • Непрочитанное: счётчик на папку, «отметить прочитанным всё старше» или «до сюда», отметка при прокрутке по знанию продукта.
  • Группировка: папки и источники, вид «заголовки» или «карточки», правила и фильтры (ключевые слова, приглушить) по знанию продукта.
  • Приоритет: у Feedly ИИ выделяет важное, у Readwise есть разделение «входящие / позже / архив» по знанию продукта.
  • Урок: «прочитано до сюда» — самая дешёвая механика, которая снимает тревогу «я что-то пропустил».
Ранжирование в стиле Hacker News и журналы изменений продукта
  • Hacker News: вес записи = очки, делённые на возраст в степени ≈1,8. Свежее и значимое поднимается, старое тонет само по знанию продукта. Для ленты изменений подходит как режим «Важное» рядом с хронологией.
  • LaunchNotes, Headway, Beamer: виджет «что нового» с красной точкой в шапке продукта. Категории (новое, улучшение, исправление), реакции, сегменты аудитории, письмо и RSS по знанию продукта.
Основы RSS и Atom
  • В Atom (RFC 4287) обязательны id, title, updated. Читалка опрашивает адрес и сравнивает записи по id, поэтому id события должен быть стабильным.
  • Фильтр живёт в адресе: /feed.atom?project=X&type=closed. Читалки не умеют входить через OAuth, поэтому для закрытых данных в адрес кладут личный токен: только на чтение, с возможностью отзыва по знанию продукта.

Сводник метрик изменений

GitHub Insights → Pulse
  • Окно: 24 часа, 3 дня, неделя (по умолчанию) или месяц. Показывает открытые и слитые PR, открытые и закрытые issues, график коммитов топ-15 авторов.
  • Рядом вкладки Contributors, Commits, Code frequency. Дельты к прошлому периоду нет — только абсолютные числа.
GitLab: Value Stream Analytics и дашборд
  • Стадии меряются от события до события: время каждой стадии и медианный lead time (от создания до закрытия). В расчёт попадают только завершённые элементы.
  • Value Streams Dashboard добавляет метрики DORA (частота деплоев, время до изменения, время восстановления, доля сбоев) и сравнение месяц к месяцу. Тариф Ultimate.
  • Урок: у метрики в своднике есть название, период и дельта, а число раскрывается в список элементов.
Linear: Insights и метрики циклов
  • Объём, начато, сделано и burn-up по циклу. Insights режет данные по времени цикла и потоку по знанию продукта.
  • Сводка Pulse — текст, а не числа: что изменилось, словами.
Datadog и Grafana: события поверх метрик
  • Деплои и инциденты ставят на графики аннотациями. В Grafana — события Graphite по тегам или деплои Vercel с фильтром по проекту и состоянию. В Datadog есть Event Stream / Events Explorer по знанию продукта.
  • Урок: событие из ленты прямо на графике объясняет скачок метрики. Для LORE это релизы и решения на графике пропускной способности.
Slack и Teams: дайджест в чат не для LORE по решению владелицы
  • Боты присылают сводку в канал по расписанию. Практика вендоров уведомлений: копить несрочное, срочное слать сразу, важное ставить в начало, давать выбрать частоту и тихие часы. Это консенсус практиков, а не исследования.
  • Slack сам шлёт письма о пропущенном по знанию продукта.
Что обычно стоит в своднике
  • Счётчики по типу: создано, закрыто, выпущено, решено — с дельтой к прошлому периоду (▲ +3).
  • Поток: пропускная способность (закрыто за неделю), время цикла (медиана и 85-й перцентиль), объём в работе.
  • Внимание: застрявшее (нет движения N дней), смена статуса на «под риском», новые блокеры.
  • Кто: разбивка «люди / агенты» и топ авторов. Это прозрачность, а не рейтинг людей.

Грабли

  • Шум от механики. Каждое поле и каждая смена статуса становятся отдельной строкой. Лечится свёрткой по объекту, окну и автору и скрытием служебных правок.
  • не для LORE по решению владелицы Усталость от уведомлений. Если всё шлётся сразу, человек отписывается от всего. Нужно разделить «срочно» (сразу) и «к сведению» (в свёртку), дать выбор частоты и тихие часы.
  • Агенты топят людей. По строке на каждое действие агента — и лента принадлежит ему. Нужны отдельный фильтр и свёртка «агент X: 14 действий».
  • Пустая лента ≠ «ничего не было». Упавшая выборка выглядит как тишина. Показывать «не смогли загрузить».
  • Метрики без определения. Время цикла все считают по-разному (в GitLab VSA — только по завершённым элементам). В подписи — от какого события до какого.
  • Нестабильный id в Atom. Читалка показывает одно событие дважды или теряет его.
  • Длинный дайджест. Его не читают. Итог в одну строку сверху, остальное по ссылке.

Что можно взять в LORE

  1. Свёртка в «Новостях». Группировать день → объект (спринт или релиз) → автор и сворачивать в строки вида «+5 закрыто в SPRINT_X», раскрытие по клику. Переключатель «Хронология / Важное»: вес как у Hacker News — значимость типа события, затухающая с возрастом.
  2. «Прочитано до сюда». Отметка последнего просмотра для каждого пользователя и разделитель «новое с прошлого визита» внутри самой ленты — без счётчиков и бейджей в навигации. Фильтр живёт в URL, отметка — нет.
  3. Atom на любой срез. Текущий фильтр «Новостей» (проект, спринт, тип, автор, люди или агенты) одной кнопкой превращается в адрес …/news.atom?… с личным токеном только на чтение. id записи = стабильный id события.
  4. Сводник за период. Создано / закрыто / выпущено / решено с дельтой к прошлому периоду, пропускная способность, медиана времени цикла с подписью «от какого события до какого», застрявшее. Каждое число раскрывается в отфильтрованную ленту.
  5. Телефон: лента на стартовом экране. Открыл приложение — сверху итог дня или недели одной строкой и карточки-счётчики с дельтой, ниже свёрнутая лента. Ничего не присылается: человек сам открывает и читает. Режим «день / неделя» и фильтр в URL, ссылки в кликабельной форме LORE.
  6. Атрибуция агентов. У события два поля: «кто сделал» (агент или сессия) и «от чьего имени» (человек). Метка «агент», фильтр «люди / агенты / все». Действия агентов по умолчанию свёрнуты.
  7. Та же лента внутри объектов. Вкладка «Активность» с мини-сводником периода на паспорте проекта, вехи, спринта и релиза — тот же компонент с запертым скоупом. Плюс маркеры релизов и решений на графиках метрик.
  8. Честные состояния и меньше шума. «Не смогли загрузить» отдельно от «за период ничего». Служебные правки (переразметка, переоткрытия строк SCD2) по умолчанию скрыты, переключатель «показать всё».
