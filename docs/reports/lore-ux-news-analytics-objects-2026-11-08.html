Новости и аналитика как отдельные объекты: как это устроено у эталонов

08.11.2026 · материал к открытому вопросу владелицы: новости и аналитика как отдельные объекты · решение не предлагается, только факты и наблюдения · метки: док — подтверждено документацией (ссылка в «Источниках»), по знанию продукта — не перепроверено в этом заходе, UNCONFIRMED — сомнительно

TL;DR

  • Новости у лидеров — хранимый объект, а не вычисляемая лента. Linear (обновление проекта/инициативы), Redmine и OpenProject (News), Confluence (блог-пост), Backstage (announcement), GitHub (release) хранят запись с id, автором, датой, телом и комментариями. Вычисляемые ленты (Jira activity stream, вкладка «Updates» в Notion, Inbox в Linear) существуют рядом и показывают события, но объектами не являются.
  • Новость почти всегда привязана к контейнеру: проекту, инициативе, пространству или репозиторию. Самостоятельная «новость ни о чём» встречается только у Backstage (там есть категории и теги).
  • Аналитика у BI-инструментов — объект с жизненным циклом (Metabase: вопрос, дашборд, модель, метрика; Grafana: дашборд и library panel). У трекеров аналитика долго была видом над набором задач (Linear Insights, Notion Chart view), но теперь и они вводят сохраняемый объект «дашборд» с владельцем и видимостью (Linear Dashboards, Plane Dashboards, Jira Dashboards).
  • Типичный набор полей объекта: id, владелец/автор, область (проект/команда/личное), видимость, тело/конфигурация, история версий, комментарии/реакции, подписка (уведомления, рассылка, алерты), ссылка (URL) и встраивание.
  • В навигации новости обычно живут вкладкой внутри проекта и дублируются агрегатом на главной. Дашборды — отдельным разделом с папками или коллекциями.

A. Новости, активность, обновления

Linear: Project / Initiative updates док

Объект. Поля: здоровье (On track / At risk / Off track), автор (первым пишет лид, дальше любой участник), rich-text тело с файлами, комментарии (уведомление в Inbox, двусторонняя синхронизация со Slack), эмодзи-реакции.

Где живёт. Последнее обновление показано на Overview проекта или инициативы. Вкладка Updates хранит всю историю вперемешку с изменениями свойств (срок, участники). Обновление инициативы подтягивает обновления подпроектов. Можно включить приход в Inbox.

Жизненный цикл. Напоминания по расписанию лиду, статус «Update Missing», если обновление просрочено. Публикация в Slack-канал.

Связь с работой. Обновление принадлежит проекту или инициативе. Явных ссылок на задачи в модели нет, только упоминания в тексте по знанию продукта.

Linear: Inbox по знанию продукта

Вычисляемая лента уведомлений по подпискам: назначения, упоминания, комментарии, обновления проектов. У элемента есть состояние «прочитано / отложено», но это уведомление о событии, а не самостоятельный контент.

Redmine: модуль News док

Объект. Поля: заголовок, краткое описание (summary), полное описание. Принадлежит проекту. Права на создание, правку и удаление задаются ролями.

Где живёт. Вкладка News в меню проекта (рядом с Issues и Wiki). Summary выводится в блоке «Latest news» на Overview проекта.

Комментарии к новости, уведомление по почте, Atom-лента по знанию продукта (на странице доков это не описано).

OpenProject: модуль News док

Объект. Заголовок, summary, описание с форматированием и макросами (например, встроенная таблица work packages). Комментарии (новые сверху). Watch / Unwatch: письмо при изменении или новом комментарии.

Где живёт. Пункт News в левом меню проекта, обратный хронологический порядок. Виджет «последние новости» на домашней странице проекта. Агрегат по всем проектам на главной, клик ведёт в проект.

Связь с работой: через макросы в теле, отдельных рёбер нет.

Jira: activity stream по знанию продукта

Вычисляемая лента событий по задачам, проектам и пользователям (гаджет на дашборде, вкладка в проекте). Своего тела, автора-«публикатора» и комментариев нет.

Confluence: блог-посты док (частично)

Объект в пространстве (space), датированный. Комментарии, лайки по знанию продукта. Подписка (watch) на страницу, блог-пост или пространство: письмо при изменении, комментарии, вложении. Есть отдельный режим «только новые блог-посты в этом пространстве» (без правок и комментариев). Именно этим режимом пользуются для анонсов.

Связь с Jira: смарт-ссылки и макросы в теле по знанию продукта.

Notion: «Updates» и история страницы по знанию продукта

Панель Updates (inbox) и история страницы — вычисляемые по правкам, упоминаниям и комментариям. Отдельного типа «новость» нет. Анонсы делают обычной страницей или записью в базе «News» с полями, которые заводит сама команда.

Plane док (частично)

Pages: проектные, вики и страницы teamspace, с версиями, комментариями и встроенными задачами. Отдельного объекта «обновление проекта» в просмотренных доках не найдено. Обновления проекта (updates) с health есть в продукте UNCONFIRMED.

Backstage: плагин announcements док (частично)

Объект в собственной БД плагина: announcement, плюс отдельные сущности category и tag. Есть REST API, интеграция с permissions, поиском (анонсы попадают в общий поиск), событиями и сигналами. Уведомление при создании отключено по умолчанию и включается флагом sendNotification. Аудит создания, правки и удаления.

Где живёт. Отдельная страница /announcements, карточка на главной, баннер последнего анонса, админ-портал.

Поля (title, excerpt, body, publisher, active, start date) по знанию продукта: в прочитанном README не перечислены.

GitHub: Releases и Discussions по знанию продукта

Release — объект репозитория: тег, автор, дата, markdown-тело, ассеты, реакции, статусы draft / pre-release / latest, опционально связанная Discussion для комментариев. Подписка через Watch → Releases only. Discussion — тред с категориями (в том числе Announcements, куда пишут только мейнтейнеры).

Obsidian, Logseq, Tana по знанию продукта

Своего типа «новость» нет. Журнал — это daily notes (страница на дату). Ленты собирают запросами (Dataview, Logseq queries, Tana live search по супертегу #update). То есть хранится заметка, а лента вычисляется.

B. Аналитика

Metabase док

Объекты: question (запрос плюс визуализация), dashboard, model, metric. Все лежат в коллекциях, у которых свои права. История: до 15 версий на объект с откатом. Новая версия пишется при сохранении, переносе, откате, удалении в корзину и верификации. Верификация контента (знак «проверено») в Pro/Enterprise.

Подписки: алерты на вопрос (по расписанию или по условию, почта и Slack), рассылка дашборда. Встраивание: публичные ссылки, guest embedding. Remote Sync (версионирование в git) в Pro/Enterprise.

Grafana док (частично)

Dashboard — объект в папке, с RBAC. uid, история версий и JSON-модель по знанию продукта. Library panel — переиспользуемая панель: правка расходится по всем дашбордам, видно, где она используется, можно отвязать. Хранится в папке, права через RBAC.

Annotation — хранимое событие на графике: время или интервал, текст со ссылками, теги, привязка к дашборду. Создаётся также через HTTP API. Тег-запрос собирает аннотации со всей организации. Это ближе всего к схеме «новость, наложенная на метрику».

Linear: Insights → Dashboards док

Insights — вид: панель справа над задачами текущего представления (custom view, команда, проект, цикл). Делятся ссылкой или CSV, сохранения как объекта нет.

Dashboards (Enterprise) — объект: один владелец (можно сменить), область видимости: workspace, команда или личный. Виджеты — это insights (график, число, таблица). Одно insight может стоять на нескольких дашбордах, добавляется из меню view. Живут в Views → вкладка Dashboards.

Jira: дашборды, гаджеты, фильтры док (сообщество)

Дашборд и сохранённый фильтр — отдельные объекты, у каждого владелец и свои права шаринга. Гаджет берёт данные из фильтра, поэтому для чужого просмотра надо делиться и дашбордом, и фильтром (частая проблема). Шаринг требует глобального права Create Shared Objects.

Notion: Chart view и Dashboard view док (частично)

Chart — вид базы данных (вкладка рядом с table/board): bar, line, donut, number. Править записи из чарта нельзя. Дашборд — либо страница с несколькими встроенными видами, либо новый Dashboard view с виджетами. Владельца и подписки у чарта как объекта нет: всё наследуется от страницы по знанию продукта.

Plane: Dashboards док

Объект уровня workspace: холст виджетов, источник — выбранный набор проектов плюс базовый фильтр. Видимость: public (все в workspace) или private (только автор, тариф Business). Отдельно есть встроенная аналитика проекта как вид и аналитика страниц.

Port и Cortex: scorecards док (Port) / по знанию продукта (Cortex)

Scorecard — объект-правило: набор правил с уровнями (Bronze/Silver/Gold, A–F), считается по сущностям каталога и показывается вкладкой на странице сервиса. В Port scorecard задаётся на blueprint, дашборды — отдельные страницы с виджетами по знанию продукта. В Cortex есть ещё Initiatives (срок и цель по scorecard).

Productboard по знанию продукта

Аналитика встроена в объекты (Insights / notes привязаны к фичам, в фиче видна сила спроса) и в сохраняемые роадмапы и вью с шарингом. Отдельного BI-объекта с алертами нет.

Наблюдения (нейтрально)

  1. Два слоя, а не один. Почти везде одновременно есть хранимая «публикация» (update, news, release) и вычисляемая «лента событий» (activity, inbox). Их не смешивают: лента показывает, что произошло, публикация — что автор об этом говорит. Linear вплетает в ленту Updates и то и другое, но визуально различает.
  2. Новость почти всегда «о чём-то». У лидеров у обновления есть контейнер (проект, инициатива, space, репозиторий) и часто структурный сигнал (health у Linear, tag у GitHub Release). Агрегат по всем контейнерам (главная в OpenProject, Inbox в Linear) строится поверх них.
  3. Аналитика дрейфует от вида к объекту. Трекеры начинали с панели над текущим списком (Linear Insights, Notion chart) и добавили сохраняемый «дашборд» с владельцем и видимостью (Linear, Plane, Jira). BI-инструменты (Metabase, Grafana) объектные с самого начала. Плюс у них есть переиспользуемый «атом» (Metabase question, Grafana library panel, Linear insight), который стоит сразу на нескольких дашбордах.
  4. Минимальный набор метаданных, который повторяется: id и стабильный URL, автор или владелец, область (проект, команда, личное), видимость. Для новостей добавляются тело, дата, комментарии, реакции и подписка. Для аналитики — источник или фильтр, история версий, алерты или рассылка и встраивание.
  5. Права наследуются от источника. Jira (фильтр и дашборд шарятся отдельно), Linear (workspace-дашборд не видит приватные команды) и Grafana (тег-аннотации утекают в публичный дашборд) показывают одну ловушку: видимость аналитики зависит от видимости данных под ней.
  6. Поиск и API. Где новость — объект, она попадает в общий поиск и API (Backstage search module, REST). Где это вид, её нельзя найти или процитировать отдельно, только страницу-носитель. Для MCP-доступа это граница между «есть id, можно сослаться» и «есть только экран».
