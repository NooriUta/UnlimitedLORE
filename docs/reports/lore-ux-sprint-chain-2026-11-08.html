S0 Страховка (без изменений UI) — первым берём только кусок, остальное параллельно (решение владелицы 08.11)

  • Контрактные тесты: все MCP-инструменты, телефонный API miniLORE, встройки Völva, доступ MCP через :4400 (старые веб-ссылки — не нужны, D-2026-UXR-NO-LINK-COMPAT).
  • Рендер-тесты (сейчас их ноль), e2e на 5 ключевых путей, замер «до».
Кусок первым (1–2 дня): контракты MCP-инструментов и API miniLORE, проба доступа MCP через :4400 — то, без чего нельзя трогать сервер. Остальное параллельно с S1–S4: рендер-тесты, e2e ключевых путей, замер «до».

S1 Сервер: честный ответ и баги

  • Метаданные полноты в ответе: время, скоуп, «обрезано».
  • Сбой одного блока вместо 502 на страницу, таймаут, body_redacted.
  • Баги B-03/04/05.
  • Категории статусов на сервере: accepted у знаний = «действует».
  • Одно правило счётчиков.
  • Найденное по дороге:
    • «сценарии фичи» отдают 0 при 5 существующих (FEAT-VP-FIT);
    • docs kind=claude-rules отдаёт 1 документ из ~10 без пометки о неполноте.
Почему: польза сразу и в v1; честный UI без этого не построить.

S2 Сервер: связи, история, память пользователя

  • Эндпоинт backlinks, общий запрос истории.
  • Виды, избранное и личные настройки на сервере, «что LORE помнит обо мне».
  • Типы рёбер для «Связать».
  • Прямой адрес бэкенда для MCP — опционально.
Почему: это данные под экраны v2; миграции только аддитивные, v1 не задевают. Идёт параллельно с S1.

S3 Инфраструктура второго приложения

  • Сервис lore-app-next, DNS и сертификат new.lore.odal…, роутер Traefik.
  • Redirect URI в Keycloak, проверка cookie.
  • Два образа в CD, проба /lore/version через :4400.
  • Флаг «новая навигация».
  • v2 — каталогом в develop (на подтверждение владелице).
Почему: чтобы UI v2 с первого дня выкатывался на стенд, не трогая v1.

S4 UI v2: каркас и списки — параллельно с S1–S3 (решение владелицы 08.11)

  • Приложения наверху, меню, аватар с настройками, мультискоуп.
  • Строка «фильтр / группировка / порядок», иконки и описание фильтров.
  • Статус-звезда, виды.
  • Касание и доступность.
  • Баги B-01/02/06–09.
Как идёт параллельно: в первый день S1–S2 фиксируем контракты новых API (форма ответа с метаданными полноты, backlinks, виды и настройки). S4 строится на заглушках по этим контрактам в каталоге web-next. Как только сервер готов, подключаем по-настоящему. На стенд S4 выходит, когда готов S3.

S5 UI v2: запись и задачи

  • Вердикт, вкладки, «ушко», режим чтения, задачи и чтение задач.
  • Правка на месте (TipTap + «код / превью»), тест «Markdown без потерь», слияние при конфликте.
  • Локальный граф, история «человек / агент».
Почему после S4: запись открывается из списков.

S6 Völva внутри LORE

  • Вкладка аналитики, блоки lore-query/lore-graph в тексте, клик = фильтр, шаблоны по типу записи.
Почему отдельно: зависит от готовности Völva (SPRINT_VIZ_EMBED); может идти рядом с S5.

S7 Новости · Админка · «Зачем» — три параллельные дорожки

  • Новости: лента и сводка без уведомлений, Atom.
  • Админка v3: журнал действий, дифф и подтверждение для опасных действий, страницы записей.
  • «Зачем»: канва раскладывается сама, «Матрица fit», «Карта историй»; UC не трогаем.
Почему в конце: самостоятельные экраны, им нужен готовый каркас S4.

S8 Переключение

  • v2 на основной адрес, v1 запасным адресом N недель, замер «после», отключение v1.

Что увидите вы

  • После S1 — честность в старом LORE.
  • После S4 — по флагу можно жить в новом.
  • После S8 — один LORE, новый.
