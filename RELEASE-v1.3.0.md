# v1.3.0 — VP-канва, самопроверка корпуса, мобильный паспорт спринта

Минорный релиз. Три новых куска функциональности (VP-канва, кнопка самопроверки, BPMN/инлайн-редактирование), несколько реальных багфиксов и большой ночной проход по мобильному UX LORE, завершившийся сегодня.

## Багфиксы, которые реально ломали работу

- **Повторный обмен OIDC-кода валил вход целиком.** `AuthCallback.tsx` запускал обмен кода на токен без защиты от повторного вызова — Keycloak-код одноразовый, второй обмен падал `400 "Code not valid"`, сессия не устанавливалась, и дальше всё уходило `401`. Причина — гонка между `useEffect` и навигацией (`replace:true` убирает код из URL только ПОСЛЕ ответа); `useRef`-гвард закрывает её вне зависимости от конкретного триггера повторного вызова.
- **Поиск по названию/телу отвечал 502** на повреждённом полнотекстовом индексе — деприцированный слайс `search` падал целиком вместо деградации. Восстановлен.
- **`component_del` не видел часть блокирующих задач** — гейт по задачам компонента проверял несуществующее плоское поле `KnowTask.component_id`, а не ребро `TAGGED_WITH`; плюс отдельная поломка: ArcadeDB не разбирает `WHERE @class` поверх `expand()`-подзапроса. Оба случая чинились в одну ночь заведения `component_del`.
- **Диаграммы в продуктовом слое** (VP-канва, use case-описания) рендерились исходником mermaid/bpmn-блока как есть, а не картинкой — общий рендерер вынесен и переиспользован из бенч-слоя.

## Новое

- **VP-канва (VP-01)** — интерактивная работа с ценностным предложением прямо на канве: связи между карточками тянутся мышью, добавление ценностей и палитра не прячутся, дроп ценности — только в свой сектор круга, сценарии заведены для квадрата.
- **MT-10 — кнопка самопроверки корпуса.** Девять существующих проверок качества (`WorkQuality`, `VpFitGaps`, гигиена связок, здоровье FT-индексов и др.) сведены в один прогон с вердиктом по каждой (`passed`/`failed`/`unavailable` — отказ проверки никогда не маскируется под «ноль находок»).
- **AL-108** — рендер BPMN 2.0 прямо в MD-полях + модалка попапа ролей в админке.
- **AL-109** — правка тела раннбука и QG прямо из просмотрщика, без перехода в отдельную форму.

## Мобильный UX LORE — сквозной проход, закрыт сегодня ночью

Паспорт спринта на телефоне был практически нечитаем: список задач уходил за нижнюю кромку экрана, а ручка, которой можно было сжать верхний блок, на узких экранах не отрисовывалась вовсе. По итогам живого тестирования на реальном устройстве почти весь спринт `SPRINT_LORE_MOBILE_UX` закрыт одним заходом:

- Статус/приоритет спринта — компактный режим и на паспорте спринта (раньше был заперт только на карточках задач); визуальный разделитель между ними.
- Фильтры по статусу/типу, блок «Контекст и привязки» (проекты/вехи/модули/ADR) и строка Проект/Релиз/PR — свёрнуты за раскрывашки на узком экране; счётчик готовности и сумма effort остаются всегда на виду.
- Карточки задач внутри фаз — почин переноса содержимого (были единственным потомком строки без собственного `flexWrap`).
- Сводка по всем спринтам и дублирующая строка вехи — скрыты, когда уже открыт конкретный паспорт (незачем на маленьком экране показывать сводку по каталогу).
- Под-вкладки главы «Как делаем» (Вехи/План/Спринты/Релизы) и легенда План-борда — сворачиваются в иконки/раскрывашку на узком экране тем же паттерном.
- iOS-автозум инпутов (MOB-09) был завязан на любое touch-устройство — Android платил ту же цену без причины; сужено до iOS по UA+`maxTouchPoints`.

## Мелкое, но по существу

- **AL-113** — типографика кнопки профиля в шапке (моноширинный шрифт для иконок случайно достался и читаемому имени пользователя).
- **AL-115** — поиск и фильтр в списке из 489 нарушений гигиены связок (раньше — голый список без единого способа найти нужное).
- **Экран «Сессия истекла»** — не нёс брендового рисунка (в отличие от реальной страницы входа Keycloak) и не подхватывал сохранённую тему/палитру; кнопка «Войти через Keycloak» → «Войти» (имя провайдера входа — не то, что нужно знать пользователю).
- **Аудит консоли браузера** — офлайн-иконки (`@iconify/react/offline`: неизвестный слаг в данных больше не даёт CSP-заблокированную попытку зафетчить его с внешнего API), убран мёртвый CDN-импорт шрифтов, контраст action-кнопок починен ещё в трёх местах (паспорт компонента, две карточки BRAGI) по тому же анти-паттерну, что и в паспорте ADR.
- Встроенные NUL-байты в двух исходниках (прятали файл от grep-тулинга, поведение не меняли) — убраны.

## Известное открытое

Одна задача осталась в работе на конец ночи: `SPRINT_LORE_MOBILE_UX/MOB-13` (мобильный паспорт спринта) подтверждена в портретной ориентации живым замером, ландшафтная — не подтверждена (инструмент эмуляции устройства в сессии не поддавался управлению). `SPRINT_LORE_MOBILE_UX/MOB-14` (браузерный chrome на телефоне не сворачивается — корневая скролл-модель `AppShell`) заведена отдельно, требует прототипа перед фиксом. Подробности — в самих задачах LORE.
