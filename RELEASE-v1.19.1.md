# LORE v1.19.1

Выпуск про то, чтобы агенты и люди работали в LORE без обходных путей.
- Git-хост теперь доступен изнутри LORE — через миниапп Forgejo.
- Запись агента всегда говорит, сделано ли действие.
- Паспорта правятся прямо на месте.
- Модель описывает сама себя реестром видов.
- Сервер сам регистрирует сессию агента.
- Закрыты issues внешнего автора по установке.

## Сессии агентов

- **Сервер сам регистрирует сессию агента** (SPRINT_LORE_AGENT_OBSERVABILITY/AO-SESSION-DOOR, #1862).
  - Повод: журнал сессий вёл только хук одного репозитория. Сессии других проектов, машин и harness в LORE не попадали, хотя код сессии и так приходил на каждом вызове.
  - Теперь любой вызов агента с кодом сессии сам заводит её запись: начало, последняя активность, машина, связь с агентом. Ни хук, ни miniLORE для этого не нужны.
  - В админке появился срез `session_coverage`: сколько записей агенты сделали с сессией и без неё — по агенту, машине и harness.
  - В истории задачи видно, кто и из какой сессии открыл версию.
  - Ценность: видно, какая сессия что делала, на любой установке.

## Forgejo из LORE (миниапп)

- **Один инструмент `forgejo` в MCP LORE** (SPRINT_FORGEJO_MINIAPP/FJ-01, FJ-02, FJ-03, #1833).
  - Повод: работа с git шла через отдельный MCP со своим токеном. Прав по ролям LORE у него не было, а в журнале действий LORE его не было видно.
  - Теперь 107 маршрутов Forgejo вызываются через LORE: права проверяются по роли до аргументов, есть защита от подмены адреса, понятные коды ошибок и курсор у длинных ответов. Карточка каждого маршрута доступна через `forgejo_describe`.
  - Ценность: агенту хватает одного MCP, а действия с git видны в LORE.
- **Чтение, запись и CI через миниапп** (FJ-04 #1839, FJ-05 #1841, FJ-06 #1842, FJ-08 #1843).
  - Проект указывается одним `git_project` вместо пары owner/repo.
  - Работа с PR и issues: создать, править, ревью; влить — только через гейт.
  - Ветки, файлы, теги и вложения релиза.
  - Журналы CI — через REST Forgejo 17.
  - Ценность: всё, ради чего держали отдельный MCP, теперь есть в LORE.
- **Гейт рисковых операций: два фактора** (FJ-07, #1844).
  - Повод: тег релиза, запуск workflow и удаление — необратимы, а агент мог сделать их одним вызовом.
  - Теперь сначала пробный прогон. Действие выполняется только с подтверждением в диалоге плюс словом человека в LORE.
  - Ценность: необратимое не происходит без человека.

## Запись агента говорит правду

- **«Ничего не сделано» — это ошибка с объяснением** (SPRINT_LORE_EXT_ISSUES_W2/ISS-06-LINK-FALSE-SUCCESS, #1824, #1836).
  - Повод: связь с незарегистрированным проектом отвечала `ok:true`, и агент считал её созданной (issue #6).
  - Теперь любая запись MCP, после которой ничего не изменилось, отвечает ошибкой «НЕ СДЕЛАНО: причина» с кандидатами. Восемь путей связи отвечают по факту ребра, а не «добавлено».
  - Ценность: агент не принимает отказ за успех.
- **MCP по адресу для любых клиентов** (ISS-04-MCP-HTTP, #1824).
  - Повод: клиентам без stdio нужен MCP по URL (issue #4).
  - Добавлены: токен шлюза, CORS, `/health`; по умолчанию слушает только локальный адрес. Запись по HTTP без Keycloak отказывается с объяснением, что включить.
  - Ценность: LORE подключается к любому MCP-клиенту безопасно.

## Паспорта и люди

- **«+ Новая» и правка паспорта** для боли, выгоды, работы, роли и фичи, с историей версий (SPRINT_LORE_ADMIN_POLISH/AP-PASSPORT-EDIT, #1829, #1835).
  - Повод: эти записи в паспорте были только для чтения, править приходилось через агента.
  - Ценность: человек сам заводит и правит их там, где смотрит.
- **Личная страница человека** с вкладками «Аналитика» и «Лента», карточка агента «чей он» (AP-PEOPLE-PAGE, #1812).
  - Учётка агента видна только админу.
  - Ценность: по клику на логин видно, что человек и его агенты делали.
- **Паспорт машины и мастер «Новая машина»** (AP-MACHINE-PASSPORT, #1812).
  - Видно, чей шлюз, какие агенты работают на машине и когда она была активна.
- **Паспорт PR** (SPRINT_LORE_MODEL_DOCS_TIDY/MD-05, #1786): ветки, задачи с названием и статусом, пометки «не влит» и «заголовок не дотянут».
- **Лента паспортов** «Контекст / Полные паспорта» (SPRINT_LORE_BOARD_PASSPORTS/BP-01-FULL-PASSPORT-FEED, #1812).
- **«Оформление» в админке и «Вид» у человека** (AP-APPEARANCE, #1828).
  - Наши стили — обязательная основа, свои — дополнительной загрузкой.
  - Пара шрифтов выбирается отдельно от палитры. Цвета словарей — токенами.
  - Ценность: установка выглядит по-своему и не ломает тёмную тему.

## Модель и реестр видов

- **Реестр видов для агентов** (SPRINT_LORE_KNOW_REGISTRY/KREG-01…04, KREG-07, KREG-08, #1795, #1802).
  - Повод: агент узнавал типы, поля и срезы по описаниям инструментов, а они расходились с кодом.
  - Теперь реестр KnowKind собирается из модели, схемы и срезов. Карточки describe выдаются из него. Если модель читается из файла, сервер говорит об этом громко.
  - Ценность: агент видит то, что реально есть в установке.
- **Модель описывает всё, что есть в базе** (SPRINT_LORE_KNOW_REGISTRY/KREG-13, #1867).
  - Повод: скиллы, супертеги, реестр видов и сессии агентов жили в базе, но не в модели — агент и экраны о них не знали, а проверка этого не ловила.
  - Теперь у них свои паспорта: скилл — с правкой; супертег — для просмотра; вид реестра и сессия агента — в админке.
  - Паспорт нового типа собирается из самой модели, без отдельного кода; сборка падает, если в базе появился тип без описания в модели.
  - Ценность: модель — единый контракт, по которому работают и экраны, и агенты.
- **Супертеги и скиллы как виды** (KREG, SKILL-01…05, #1802): KnowSkill со своими правилами записи, срезами и describe.
- **Язык отбора над срезами** (KREG-12, #1845, #1850).
  - Фильтры in / not_in / range / empty / contains по описанным полям — над любым GET-срезом.
  - Ценность: агент берёт нужные строки, а не всю выдачу.
- **Подписи связей на трёх языках** ru / en / pl и единое имя момента создания `created_at` (KREG-10, #1802, #1832).
- **Зависимость задача → задача** через `task_link rel="dep"` (KREG-11, #1796).
