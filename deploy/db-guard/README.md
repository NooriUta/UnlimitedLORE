# Сторож входов в ArcadeDB (DBR-07)

Задача: SPRINT_LORE_PRODUCT_BACKLOG/DBR-07. ArcadeDB 26.11 успешных входов не журналирует (проверено на LORE-ygg 06.11.2026), поэтому «кто, когда и откуда вошёл под root» видно только тому, кто стоит на пути запроса.

## Что делает

- Обратный прокси перед `arcadedb:2480`. Запрос уходит в базу как есть, вместе с заголовком `Authorization`.
- Из заголовка берётся только имя. Basic даёт пользователя, пароль отбрасывается сразу. Bearer даёт `apitoken:<имя>` по отпечатку из настройки, а если отпечатка в настройке нет — `apitoken:(unknown)`.
- Первый вход пары «пользователь × источник» за календарную минуту пишется точкой в ряд `AuditDbLogin`: время, адрес источника, имя контейнера, база, метод, путь без строки запроса и без текста SQL, статус ответа.
- Вход под root вне `GUARD_ROOT_SOURCES` даёт событие тревоги. Канал владелицы пока не подключён: точка расширения — `stubNotify` в `guard.mjs`, сейчас событие пишется только в журнал.
- Заголовков и тел сторож не пишет ни в журнал, ни в ряд. Это проверяет тест «секрета нет ни в записи, ни в журнале».

## Чего сторож не делает: Этап 6

Прямой порт `:2480` сторож **не закрывает**. Пока клиенты ходят в базу мимо прокси, ряд неполон, и «записей нет» ничего не значит. Закрыть порт и пустить бэкенд через сторожа (`LORE_DB_ENDPOINT=lore-db-guard` в профиле установки) — это Этап 6 по D-2026-SETUP-BEFORE-ENFORCE. Он делается отдельным шагом и только с разрешения владелицы.

## Ряд и права

- Ряд объявлен в модели 1.18: `shared/model/lore-model.json`, раздел `series.AuditDbLogin`. В новой базе его заводит шаг 3 установщика переноса (`scripts/model-migration/series.mjs`). DDL у бэкенда (`LoreModelSeries.ddl`) и у установщика совпадает, это сверяют тесты.
- Сторож пишет своим токеном группы `db-guard`. У группы одно право — `createRecord` на `AuditDbLogin`; прав на схему и на остальные типы нет. Фрагмент `server-groups.json` строит `guardGroup()` в `scripts/model-migration/series.mjs`.
- Под root сторож не стартует. Исключение — `GUARD_REHEARSAL=1`, только для репетиции на копии базы.
- Как выпустить токен ArcadeDB для группы — по документации ArcadeDB установленной версии. В этом репозитории выпуск токена не автоматизирован (гипотеза: через Studio или API сервера; не проверено).

## Настройка (переменные окружения)

| Переменная | Что |
|---|---|
| `GUARD_UPSTREAM` | адрес базы, по умолчанию `http://arcadedb:2480` |
| `GUARD_PORT` | порт сторожа, по умолчанию 2480 |
| `GUARD_DB` | база, в которой лежит ряд |
| `GUARD_DB_AUTH` или `GUARD_DB_AUTH_FILE` | заголовок записи целиком, `Bearer <токен>`. Пусто — ряд не пишется, в журнале предупреждение |
| `GUARD_ROOT_SOURCES` | известные источники root: имена контейнеров, адреса IPv4 и сети CIDR через запятую |
| `GUARD_TOKEN_NAMES` или `GUARD_TOKEN_NAMES_FILE` | строки вида `sha256:<16 hex> имя`. Отпечаток считает `principalOf.fingerprint` из `lib.mjs` |
| `GUARD_DOCKER_SOCKET` | путь к docker-сокету, чтобы узнавать имя контейнера по адресу. Доступ к сокету равен доступу ко всему docker, подключайте осознанно |

В профиле установки сторож включается так: `COMPOSE_PROFILES=guard` (сервис `lore-db-guard` в `deploy/install/docker-compose.install.yml`).
