# v1.15.0 — единое время в базе, страницы и проекции у слайсов, сторож закрытых спринтов, LORE на ArcadeDB 26.11.1

Минорный релиз: 15 PR (#757–#775) после v1.14.0. Главное — время истории переведено в нативный DATETIME одной миграцией (V56), у любого слайса появились `limit`/`offset`/`fields`, в закрытый спринт больше нельзя завести задачу, а прод-база LORE обновлена до ArcadeDB 26.11.1 после проверки всех жильцов инстанса.

## Время в базе — один формат (`SPRINT_LORE_ROADMAP_PER_PROJECT/RM-P13`)

- **Миграция V56** (#769): `valid_from`/`valid_to` у всех 12 типов истории (`*Hist`) — нативный DATETIME, как рекомендует ArcadeDB. Раньше у десяти типов время было текстом, у двух — DATETIME, и внутри одной строки левая граница была строкой, а правая датой. На проде (05.11, 12:34–12:51 UTC) по каждому типу «непустых до = после», нераспознанных значений 0, WARN 0; задачи — 12 278 строк.
- **Выдача — ISO-8601 UTC с `Z` во всех JSON-ответах** — одним фильтром ответа сервера. База отдаёт DATETIME без зоны (`2026-04-13 00:00:00.000`), а браузер читает такую строку как МЕСТНОЕ время — у спринтов даты могли сдвигаться на часовой пояс читателя. Формат самой базы не трогаем: замер (#768) показал, что `ALTER DATABASE dateTimeFormat` на 26.10.2 даёт битую строку `…171Z.171`.
- `KnowRunbookHist.valid_to` в коде был STRING, на проде — DATETIME: свежая база в CI теперь совпадает с продом. `updated_at` решений пишется в UTC.

## Слайсы: страницы, проекции, пакетное чтение (`SPRINT_LORE_PRODUCT_BACKLOG/SE-01`, `SE-08`)

- **`limit`, `offset`, `fields` у ЛЮБОГО слайса** (#758): `releases?limit=1&fields=release_id,is_current` вместо ~20 тыс. знаков описаний всех релизов. Урезанный ответ это сообщает — `_page {limit, offset, total, has_more, fields}`; опечатка в `fields` — 400 со списком доступных колонок; на пустой выдаче — честное «колонки не проверены».
- **`tasks_by_uids`** (#761) — заметки задач пачкой по списку `СПРИНТ/КОД`.
- **`releases` отдаёт текущий релиз первым** (#763): `limit=1` раньше возвращал случайный релиз той же даты.
- **`task_starts` отдаёт `task_uid`** (#775): по голому коду нельзя было соединить старты со спринтом — 220 кодов задач встречаются в нескольких спринтах.

## Задачи и роли (`SPRINT_LORE_MEASURE_TRUTH`)

- **В закрытый спринт задачи не заводят и не переносят** (#770, MT-SPRINT-DONE-GUARD): `task_new`/`task_mv` в спринт done/cancelled — отказ 400 с именем спринта, датой закрытия и тем, что делать. Повод — два DONE-спринта Völva с 11 открытыми задачами. `status_set` унаследованных задач не запрещён.
- **`task_mv` сохраняет статус** (#771): перенесённая задача больше не сбрасывается в PLANNED.
- **`task_new` принимает `effort_days`** (#758) — всё, что пишет `task_set`, принимает и `task_new` (тест-правило).
- **Имя агента сводится к его id** (#772): «Claude Code (full)» — как роль показывается при чтении — теперь принимается и при записи.

## Агенты и MCP (`SPRINT_LORE_AGENT_OBSERVABILITY/AO-07`)

- **Агент `full` заявляет профиль на действии** (#764): заголовок `X-Lore-Act-As` (MCP — переменная `LORE_ACT_AS`) — запись проверяется матрицей заявленного профиля, заявка только сужает права; профиль, закреплённый своим клиентом, заголовком не меняется.
- **`lore_version` показывает сборку, которую исполняет процесс** (#765), а не файл на диске: после пересборки MCP вердикт `restart_needed`, пока сессия не переподключена. Раньше он отвечал «drift: ok» при старом коде в памяти.

## Админка

- **«Глобальные роли»** (#757): блок realm-ролей Keycloak в карточке человека назван понятно, с пояснением «действуют во всех проектах».
- **Группа «MCP» в админке** (#757): «Инструменты MCP» и «Подключения». **Справочник MCP полный — 98 инструментов** вместо 60; гвард сверяет экран с кодом сервера.
- **Список проектов для гейтов задаётся в «Настройках»** (#762, `SPRINT_QG_REBUILD/QG-09`): ключ `qg.actions_projects` вместо переменной окружения. Известные настройки теперь правятся; `md_images_enabled`/`md_image_max_mb` больше не числятся «неопознанными».

## Инфраструктура (без кода)

- **Прод-база LORE-ygg — ArcadeDB 26.11.1** (05.11, 13:08 UTC, простой ~17 с). До обновления — проверка всех шести баз инстанса: бэкенд-набор LORE на временном 26.11.1 зелёный (#773), дым-проверка miniLORE, аудит RAGVSDL, проба MIDGARD. Перед сменой — бэкап всех баз с проверкой архивов; счётчики до и после совпали.
- **Тестовые базы LORE-ygg-ci и LORE-ygg-test** — тоже 26.11.1 и впервые с лимитом памяти (6 и 2 ГБ; раньше куча по умолчанию до 16 ГБ при сегодняшних OOM на хосте).
- **Восстановление из бэкапа на 26.11.1** — распаковкой архива: `RESTORE DATABASE … file://…` в 26.11.1 по умолчанию запрещён. RUNBOOK-LORE-SCHEMA-UPGRADE дополнен.

## Совместимость

- Миграция V56 накатывается шагом CD; перед ней раннер снимает бэкап. Повторный прогон ничего не меняет.
- Время в JSON-ответах — `…T…Z` с миллисекундами. Код, который разбирал форму «через пробел», продолжит работать: такая форма больше не приходит.
- Слайсы без `limit`/`offset`/`fields` отвечают как раньше — голым списком.
- ArcadeDB 26.11.1: недостающий именованный параметр SQL — 400 (раньше молча null). Весь бэкенд-набор LORE на 26.11.1 зелёный.
