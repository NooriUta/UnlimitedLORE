# v1.1.1 — аналитика продуктового слоя: вкладка «Продукт»

Patch-релиз: экран 8 прототипа PL-01 доехал до продукта. В разделе «Аналитика» появилась вкладка **«Продукт»** — ни одна цифра на ней не вводится руками, всё вычислено из графа (ADR-LORE-030). Бэкенд был готов заранее (слайсы AN-01…08), релиз добавляет UI-слой и закрывает фазу `PHASE_UI_PRODLAYER`.

## Вкладка «Продукт» (AN-13…AN-18)

- **E · Гигиена связок — первой очередью.** `product_hygiene`: uc-задачи без REALIZES, enb-задачи без ADR, UC без приёмки, боли без снятия — с предупреждением из прототипа: «пока тут не ноль — остальные цифры врут». Находки кликом ведут в спринт/фичу.
- **VP-таблица по фичам.** `feature_vp_analytics`: fit по трём осям (работы·боли·выгоды), причём выгоду замыкает **только измеримая доставка** — доставка без метрики честно показывается отдельной причиной (ADR-032 §2). Клик по fit раскрывает, что именно не замкнуто. «Ценность доехала» = работы, выполняемые shipped-сценариями (D17). Строки — deep-links в карточку фичи и вехи.
- **A · Карта нагрузки ролей.** `actor_load` через глобальный проектный селектор шапки (AL-78): выбран проект — один вызов, «все проекты» — по каждому и слияние. Мёртвые роли (0 UC) помечены.
- **B · Стратегическое покрытие.** Обе стороны `TARGETS_MILESTONE`: фичи без вехи (ценность вне стратегии) и вехи без фич (цель без реализации).
- **D · Инвестиционный профиль.** Доли UC/JTD/ENB по релизам, считаются по `effort_days`; если у части задач релиза оценки нет — весь релиз честно считается «по штукам» с явным флагом (веса и штуки в одной доле не смешиваются).
- **F · Качество оформления.** Батч `GET /uc/quality/all` — тот же Java-линтер UcQuality, что в форме UC (правила не дублируются, ADR-027 D3), нормированные оценки; ниже порога — раскрывающийся список.
- **C · G · I — включаются позже**, с причинами: shipped-динамика ждёт накопления `shipped_at`, граф линейки — наполнения «Мест в линейке», реинжиниринг — `in_rework` (ADR-029). Блокеры вынесены в `SPRINT_LORE_PRODUCT_BACKLOG`. **H** — ссылка в реестр акторов.

Агрегации — чистые функции с 10 юнит-тестами (fit 5/6 из прототипа воспроизводится тестом дословно). Ленивая загрузка: вкладка не утяжеляет общий экран аналитики. Падение одного среза не гасит остальные.

## Безопасность: dependabot-волна (issue #299)

Закрыто 7 из 9 уязвимостей GitHub-зеркала: `fast-uri` ×2 (high, host confusion), `hono` ×3, `@hono/node-server` (path traversal) — mcp-server теперь `npm audit` чистый; плюс `brace-expansion` (high, DoS) в корне. **Не закрыто осознанно:** `react-router`/`react-router-dom` (2 moderate) — фикс существует только в v7, мажорная миграция роутера отдельной задачей, issue #299 остаётся открытым на неё.

## Уборка спринтов

Закрыты `SPRINT_LORE_PRODUCT_FIT` и `SPRINT_LORE_ADMIN_PANEL` (эпик v1.1.0). Хвосты, заблокированные данными корпуса (FIT-04, AN-06, AN-09), — в новом `SPRINT_LORE_PRODUCT_BACKLOG`; проектная ось чтения (AL-91…96) — в новом `SPRINT_LORE_PROJECT_SCOPE`.
