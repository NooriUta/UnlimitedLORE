# v1.12.1 — лента видит все проекты спринта, uc_link честно называет смену роли, CI перестал трогать прод-СУБД

Патч-релиз: 5 PR (#692, #694, #696, #697, #698), набранных после среза v1.12.0. Два дефекта чтения/записи, два исправления CI и тест-инварианты карты продукта.

## Исправления

- **Лента (`/lore/news`) брала только первый git-проект спринта** (#696, `SPRINT_LORE_PROJECT_SCOPE/PS-NEWS-SPRINT-ALL-PROJECTS`). События «спринт заведён», «задача заведена» и «задача закрыта» несли проект из первого элемента списка — у спринта, принадлежащего двум репозиториям, второй исчезал из группировки. Причина в чтении, не в данных: `sprintProject` хранил `l.get(0)`. Теперь события несут весь список (контракт SE-05: одна строка, `projects` — отсортированный список, `project` — первый из него). Живой тест на ДВУХ проектах: на одном старое и новое поведение неразличимы.
- **`uc_link` с ролью актора** (#694, `SPRINT_LORE_PRODUCT_BACKLOG/MT-12`):
  - смена роли уже связанного актора отвечала `unchanged` — теперь `updated` с `role_before`/`role_after`;
  - повторная привязка БЕЗ роли переписывала роль на значение по умолчанию. Причина: `CREATE EDGE … IF NOT EXISTS` возвращает строку существующего ребра, и «связано сейчас» читалось как «связано впервые». Свежесть ребра теперь берётся из пробы ДО записи.

## Тесты

- Инварианты карты продукта (#692, `SPRINT_LORE_ROADMAP_PER_PROJECT/RM-T1`): чужое не видно, пустая веха видна, направление ребра проверено живым тестом.

## CI

- **Упавшие тесты больше не повторяются трижды** (#697, `SPRINT_LORE_CI_MIRROR/CIM-09`). Ретрай gradle задуман для обрыва канала до Maven Central, а повторял и честно красные тесты — PR с тремя упавшими тестами держал раннер 52 минуты вместо ~15. Теперь при «упало N>0» скрипт останавливается сразу; обрыв сети по-прежнему повторяется. У скрипта есть самопроверка, она идёт шагом CI.
- **Live-DB тесты CI ушли с прод-СУБД** (#698, `SPRINT_LORE_CI_MIRROR/CIM-11`). Раньше тестовые базы создавались на прод-ArcadeDB (:2480). Теперь — отдельный контейнер `LORE-ygg-ci` (26.10.2, порт :2482, только на docker-мосту); запасного пути на прод нет — недоступность тест-СУБД валит прогон громко.
- Выделенный раннер LORE поднят до ёмкости 4 (`SPRINT_LORE_CI_MIRROR/CIM-10`, инфраструктура, без кода).
