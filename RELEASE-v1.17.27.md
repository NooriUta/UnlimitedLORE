# LORE v1.17.27

Кто, из какой сессии, с какого harness и с какой машины правил запись — теперь в каждой версии истории. Тип гейта качества по справочнику, вход через Keycloak и Völva в пакете установки по выбору, клиенты мостов LORE совместимы с новыми версиями Infisical. Миграций схемы нет.

## История записи: кто и откуда правил

- **Код сессии агента в каждой новой версии истории** (SPRINT_LORE_AGENT_OBSERVABILITY/AO-SESSION-LOG, #1574). Повод: по истории записи было видно, какой агент её менял, но не из какого диалога. Теперь MCP передаёт код сессии Claude Code, и версия хранит его в поле changed_by_session. Найти разговор, в котором появилась правка, можно прямо по истории.
- **Harness и машина правки — со сверкой** (SPRINT_LORE_AGENT_OBSERVABILITY/AO-SESSION-LOG, #1574). Повод: один агент работает в разных оболочках и на разных машинах, а история их не различала. MCP передаёт harness и машину из своих настроек, сервер сверяет их со справочником и клиентом Keycloak, расхождение помечает в changed_by_harness_note, а не скрывает. Код машины всегда строчными.
- **Новые служебные поля — во всех перечнях** (SPRINT_LORE_AGENT_OBSERVABILITY/AO-SESSION-LOG, #1575). Повод: новое поле, которого нет в перечне служебных, всплыло бы в паспорте блоком «Не описано в модели» и попало бы в сравнение версий. Поля сессии, harness, машины и пометки сверки — в общем перечне служебных полей сервера и модели. Правка человека пишет туда пусто.

## Гейты качества

- **Тип гейта по справочнику: универсальный или проектный** (SPRINT_QG_REBUILD/QG-04, #1572). Повод: гейты общего назначения и гейты одного проекта жили в одном списке без признака. Теперь у гейта поле qg_type из справочника qg_type, MCP qg_new принимает его, неизвестный тип отбивается.

## Установка

- **Вход через Keycloak и встраивание Völva — по выбору** (SPRINT_LORE_MODEL_DOCS_TIDY/MIG-04, #1579). Повод: пакет установки ставил LORE только без входа, и подключить свою область Keycloak можно было лишь правкой файлов руками. Теперь в .env пакета есть переключатель входа, адрес и клиент Keycloak, ключи Völva. По умолчанию всё как раньше — без входа. Самопроверка пакета выросла с 39 до 52 проверок.

## Исправления

- **Клиенты мостов LORE — только HTTP/1.1** (#1577). Повод: Infisical v0.167 отвечал 405 на попытку перейти на HTTP/2 без шифрования, и сервер стартовал без секретов. Клиенты мостов теперь всегда говорят по HTTP/1.1 — это работает и со старыми, и с новыми версиями.

## Технологии

- Без смены версий движков и зависимостей.
