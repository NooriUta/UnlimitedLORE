# Спайк: 500 стикеров на телефоне — производительность React Flow

Задача: SPRINT_UXR_S7C_WHY_CANVAS/S7C-07. Контекст: холст «Зачем» на `@xyflow/react`
(SPEC-LORE-UXR-WHY-CANVAS-TECH, отчёт `docs/reports/lore-ux-why-canvas-tech-2026-11-08.html`), новый UI только на React (D-2026-UXR-KIT-REACT).
Код самодостаточный, в `src/`, `web-next/` и `kit/` ничего не менялось.

## Вывод коротко

- **500 стикеров на телефоне — нормально.** При «memo + LOD» в эмуляции телефона (CPU 4× медленнее) загрузка 0,58–0,60 с,
  95-й перцентиль кадра при панораме и щипке ≤ 12 мс (то есть не хуже 60 fps), отклик перетаскивания 18 мс по медиане и 21–23 мс в p95, куча 11,4 МБ.
- **1000 тоже выдерживает, но уже с запасом впритык:** без LOD p95 кадра при панораме всего холста доходит до 30 мс, загрузка 0,8–1,8 с, куча 20 МБ.
- **`nodeTypes` вне компонента + `memo` для узла обязательны.** С inline-`nodeTypes` перетаскивание касанием **не работает вообще**
  (причина доказана, см. ниже) — дело не в скорости, это поломка.
- **На виде «весь холст» касание цепляет стикер вместо холста:** стикер там 9–27 px, и «подстройка касания» Chrome
  притягивает палец к ближайшему узлу. Это UX-ограничение, его надо решить в S7C-02 (см. рекомендации).

## Что и как мерили

- Страница: N стикеров (100/300/500/1000) 160×100 с заголовком и 9–14 словами текста, N−1 рёбер; раскладка «сеткой с дрожанием»,
  позиции детерминированы (`mulberry32`, seed 7). Production-сборка Vite (React 19.3.1, @xyflow/react 12.12.1 — мажор 12, как в корневом `package.json`).
- Браузер: Playwright + Edge 157 (headless, `channel: 'msedge'`), эмуляция телефона 412×915, deviceScaleFactor 2.6, `isMobile`, `hasTouch`,
  **CPU throttling 4×** через CDP `Emulation.setCPUThrottlingRate`. Хост: Intel Core Ultra 9 275HX.
- Жесты — настоящие касания через CDP `Input.dispatchTouchEvent`: панорама одним пальцем 3 с (вид «весь холст» и масштаб 1),
  щипок двумя пальцами 3 с (масштаб ×4 туда и обратно), перетаскивание стикера на масштабе 1 (60 шагов).
- Метрики:
  - **загрузка** — от начала навигации до момента, когда все узлы измерены (`useNodesInitialized`) + 2 кадра;
  - **кадры** — счётчик `requestAnimationFrame` во время жеста: fps и 95-й перцентиль длительности кадра.
    В headless rAF не привязан к 60 Гц (потолок ~165 fps), поэтому **главная цифра — p95 кадра**: ≤ 16,7 мс = держим 60 fps;
  - **drag** — от `timeStamp` касания до кадра после коммита нового положения узла (p50/p95);
  - **куча** — `Runtime.getHeapUsage` после принудительного GC;
  - **DOM** — число `.react-flow__node` в DOM на виде «весь холст» и на масштабе 1.
- Положительный контроль жестов: в каждом кадре пишется вид холста; в таблице рядом с fps — насколько вид реально сдвинулся (px)
  или во сколько раз изменился масштаб (×). «Не сработал» = вид не двигался, fps в такой ячейке ничего не значит.
- Варианты: `base` — inline `nodeTypes` и узел без `memo` (анти-паттерн); `memo` — `nodeTypes` вне компонента + `React.memo`;
  `memo+lod` — плюс уровень детализации (на масштабе < 0,5 текст стикера не рисуется; подписка `useStore` на булев признак,
  перерисовка только при пересечении порога); `memo+lod+ovr` — плюс `onlyRenderVisibleElements`.
- Каждый замер выполнен **дважды** (два полных прохода матрицы), в ячейках «прогон 1 / прогон 2». Сырые данные — `results/results.json`.

### Почему ячейки «не сработал»

1. **`base`: перетаскивание и панорама на масштабе 1 мертвы.** Причина проверена отдельным прогоном: при касании узел выделяется →
   родитель перерисовывается → inline-объект `nodeTypes` новый → React Flow перемонтирует компонент узла → DOM-элемент под пальцем
   отсоединяется (`isConnected: false` сразу после `touchstart`, у `memo` — `true`). События касания по стандарту продолжают
   приходить на исходную цель, она уже вне документа, до обработчиков React Flow они не всплывают. Бесконечного цикла перерисовок
   нет (0 рендеров за секунду простоя в обоих вариантах) — это поломка именно касания.
2. **Панорама «весь холст» при N=100 (и частично при 500):** на fitView стикер шириной 9–27 px, а Chrome подстраивает касание под
   ближайший интерактивный элемент. Даже когда `elementFromPoint` в точке касания возвращает пустой холст (с запасом ±10 px),
   `touchstart` уходит на `.sticky` — палец берёт стикер, а не холст. При 500 жест сработал лишь отчасти (сдвиг 94–231 px из ~225 возможных).
   На реальном пальце (пятно контакта 7–10 мм) это будет только хуже.

## Рекомендации для S7C-02

1. **`nodeTypes` — константа на уровне модуля, компонент стикера — `React.memo`.** Без этого перетаскивание касанием не работает (см. выше).
   Колбэки (`onNodeDrag` и т.п.) — через `useCallback`.
2. **LOD обязателен:** ниже масштаба **0,5** рисовать стикер плашкой без текста. Подписка — `useStore(s => s.transform[2] < 0.5)`
   (булев селектор: узел перерисовывается только при пересечении порога). При 1000 это снимает p95 кадра панорамы с 18–30 до 12 мс.
3. **`onlyRenderVisibleElements` включать при N ≥ 300.** Плюс: на рабочем масштабе в DOM ~20 узлов вместо 500–1000,
   лучший drag (p50 ≈ 15 мс). Минус: при щипке на виде «весь холст» p95 кадра растёт (6 → 12 мс при 500, до 24 мс при 1000),
   потому что видимое множество пересчитывается на каждом шаге масштаба. Для 100–300 стикеров не нужен.
4. **Касание на мелком масштабе:** при масштабе < 0,5 отключать перетаскивание узлов (`nodesDraggable={zoom >= 0.5}`
   через тот же булев селектор) — тогда одним пальцем всегда двигается холст. Перемещать стикер — на рабочем масштабе
   или по долгому нажатию (оно уже есть в плане S7C-02).
5. **Лимиты:** 500 стикеров на холст — целевой объём, укладывается с запасом. **Мягкий лимит — 1000** (загрузка до ~1–1,8 с,
   куча ~20 МБ, кадры на грани): после 1000 предупреждать и предлагать делить на рамки или отдельные холсты.
   `minZoom` — 0,05 (иначе 1000 стикеров не помещаются в экран телефона), `maxZoom` — 2.
6. **Приёмка S7C-02 — на реальном телефоне.** Эмуляция не воспроизводит растеризацию GPU телефона (на deviceScaleFactor 2,6
   перерисовка текста при щипке — главный риск) и подстройку касания реального пальца. Нужна короткая проверка на
   среднем Android (500 стикеров, панорама/щипок/перетаскивание).

## Как повторить

```bash
cd spikes/canvas-perf
npm install
npm run build
node measure.cjs 2          # два полных прохода, ~10 мин; NS=500 node measure.cjs 1 — один размер
node summarize.cjs          # таблица из results/results.json
```

`measure.cjs` отдаёт `dist/` через `page.route` (без сетевого сервера), Playwright берётся из `C:/AIDA/TestPlayGround/node_modules`.
Параметры страницы: `?n=500&memo=1&lod=1&ovr=1`.
