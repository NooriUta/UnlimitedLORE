# v1.13.0 — честные исходы записи, форма задачи, доступ к ArcadeDB по своему токену, «текущий» релиз сам по тегу

Минорный релиз: 16 PR (#687–#720), набранных на `preprod` после v1.12.1 и обкатанных на стенде. Главное — ответ записи теперь говорит о том, что случилось в графе, а не о том, какие команды выполнились: по ходу найдены и закрыты тихие порчи данных при `ok:true`.

## Исходы записи и тихие порчи (ADR-LORE-043, `SPRINT_LORE_DB_RESILIENCE/DBR-17`)

Ответы записи несут `outcome` (created / updated / unchanged / deleted / noop + причина), выведенный из факта в графе. Раскатано на все оставшиеся ресурсы (#710, #714, #715, #719): spec, release, QG, вопросы, ранбуки, компонент, справочник, проект, пользователь/роль, ассет, продуктовая ось, автопривязка Forgejo.

Найденные порчи:

- **spec/link** `replace` на несуществующую цель сносил текущую привязку и потом отвечал 404; `remove` непривязанного компонента снимал настоящую привязку.
- **spec/link `add`, release/link, автопривязка PR** шли без `IF NOT EXISTS`: повтор создавал второе ребро, у спринта копилось по `IMPLEMENTED_IN_RELEASE` на каждый мерж.
- **release/link** считал `sprints_linked` по выполненным командам (несуществующий спринт → `sprints_linked:1` при нуле рёбер); к несуществующему релизу отвечал 500 (NPE в `WorkQuality.compact(null)`).
- **QG**: прогон без гейта, рекомендация без прогона, промоут в несуществующий спринт создавали сирот при `ok:true`; повтор промоута заводил вторую задачу. Теперь — 404 до записи, повтор — `unchanged`.
- **component**: update/link-parent по несуществующему id отвечал `ok:true`; повтор create плодил второе `PARENT_OF`, смена родителя оставляла прежнего — два родителя.
- **product/link**: неверная роль на `add` снимала существующую связь и только потом отвечала 400.
- **user/role**: выдача роли в незарегистрированный проект писалась в журнал при нуле рёбер.
- **dict**: каждый повтор открывал пустую Hist-ревизию.
- **Схема**: не было индекса `KnowPR(pr_uid)` — на чистой базе `release_link(pr)` и автопривязка PR отвечали 400.

## Форма задачи (`SPRINT_LORE_MEASURE_TRUTH/MT-TASK-SHAPE`, #717, #720)

- `TaskShape`: скелет заметки (почему / шаги / критерий / тест / проба), класс S/M/L/XL по факторам и сверка с `effort_days`; рекомендации epic / merge / steps / verify / test / probe / estimate.
- Подсказки `shape_*` в ответе `task_new` / `task_set` / пакетного `quality` — счёт качества не меняется.
- `GET /lore/task-shape` и MCP-инструмент `task_shape` — строки на задачу без текста заметки + сводка по проектам (вход для Völva).
- v2: шаги в жирной разметке и «Шаг N», буквальный `\n` нормализуется, обзорные и итоговые разделы не утяжеляют класс. Калибровка по 5310 задачам — медиана цикла S 1,47 / M 1,61 / L 2,88 / XL 6,83 дня, монотонно.

## ArcadeDB и деплой (`SPRINT_LORE_DB_RESILIENCE`)

- **Рантайм по своему токену без updateSchema** (#703, DBR-01/DBR-06): `lore.mart.auth = basic | token`; накатка схемы — отдельным шагом CD (`lore.migrate.only`), перезапуск контейнера больше не накатывает схему молча.
- **CD проверяет работу, а не наличие** (#690): readiness с базой нашим кредом; бандл фронта проверяется тот, на который ссылается `index.html`, по типу.
- **Проба мостов** (#710, #712): health-группа `bridges` — живая проба KC и Forgejo; исправлен NPE от чтения поля CDI-прокси, гейт мержа снова с grace-окном 300 с. Сторож `InjectedBeanFieldAccessTest` ловит этот класс ошибок.
- KC без умолчания `localhost:18180` (#710).

## Релизы

- **«Текущий» релиз переключается сам** по тегам Forgejo (#702), без токена записи в CI; сверка не уводит флаг назад, если тега текущего нет в репозитории (#707).

## Срезы и MCP

- Пакетный срез отдавал `[]` на нескольких спринтах: параметры `*_ids` теперь уходят в СУБД списком (#689).
- `task_new` с занятым кодом — 409 `TASK_ID_TAKEN` с `suggested_task_id` вместо 502 (#691).
- Сверка доков (#708, `SPRINT_LORE_MCP_DOCSYNC_GAPS`): `specs` и `docs` принимают `project`, доки отдают SHA-256 и длину тела, статус спеки — словарь `spec_status`; `project_new` отдаёт owner создателю; новый `project_role_set`; `query_slice` не теряет признак усечения.
- Создающие вызовы (`adr_new`, `doc_new`, `spec_new`, `runbook_new`, `question_new`) принимают `project` (#710); `sprint_new` пишет `priority`; срез `releases` принимает `project` и не режет выдачу на 200.

## QG

- Исполнитель рутин канала 2 (#693, `SPRINT_QG_REBUILD/QG-11`, шаг 1): попытка пишется до работы, надзиратель закрывает зависшие как ABORTED. Рабочих рутин пока нет, все выключены по умолчанию.

## Интерфейс

- Справочник `agent_role` → `agent_profile` (#687): «профиль агента» и «роль доступа» вместо одного слова «роль»; карточка продуктового актора — «роль в продукте».

## Совместимость

- **Миграции V48–V51** (уже накатаны на стенде): V48 — `agent_role` → `agent_profile`; V49 — хеши тел доков; V50 — словарь `spec_status` и `KnowSpecHist.status`; V51 — снос легаси-рёбер `HAS_STATUS` у `KnowADRHist` (с выгрузкой в лог).
- compose: `lore.migrate` по умолчанию `false` — схема накатывается шагом CD, а не стартом бэкенда.
- Ответы записи получили ключ `outcome`; старые ключи (`linked`, `added`/`removed` и т.п.) сохранены.
- Новые отказы вместо прежнего `ok:true`: 404 `TARGET_NOT_FOUND` при несуществующей цели (component, user/role, QG, spec/link); 409 `TASK_ID_TAKEN` у `task_new`.
- Статус спеки — только код словаря `spec_status`; свободный текст — 400 с перечнем допустимых.
