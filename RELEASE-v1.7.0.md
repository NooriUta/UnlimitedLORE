# v1.7.0 — качество на записи, читаемая лента, разбор кода

Минорный релиз поверх v1.6.0, 21 изменение. Главное — **вердикт полноты возвращается в ответе на запись**: LORE перестала быть местом, где незаполненное поле обнаруживается через месяц по срезу. Плюс новостная лента стала отвечать на вопрос «что изменилось», а не «сколько было событий», и закрыта пачка находок разбора кода.

## Качество записи (ADR-LORE-039)

Линтер полноты `WorkQuality` существовал, но звался только из self-check — то есть постфактум и лишь если кто-то откроет срез. Теперь вердикт приходит **в момент записи**, пока автор ещё держит сущность в голове.

- **Покрыты все типы:** task, sprint, phase, release, adr, decision, spec, component, milestone, question. UC остаётся под своим `UcQuality` (ADR-LORE-027) — у него свой набор Cockburn-проверок и своя форма.
- **Компактная форма ответа.** Раньше вердикт эхом перечислял все проверки, включая пройденные — три десятка строк на каждую запись. Теперь: OK → одна строка `«task: все проверки ok (6/6)»`; не-OK → только проваленные и обязательно с текстом (код без сообщения заставляет лезть в документацию, то есть отвлекает ровно там, где надо действовать). Батч сворачивается: прошедшие числом, поимённо только проваленные.
- **Механические проверки ADR + вес по статусу.** По образцу UC-линтера судится СТРУКТУРА, не содержание: пороги содержательности контекста и решения, трассируемость (ссылка на `ADR-*`/`D-*`), когерентность (`SUPERSEDED` без ребра SUPERSEDES — утверждение о замене, которое нечем проверить). Один и тот же список проверок даёт разный знаменатель: `PROPOSED` — черновик, не давим; `ACCEPTED` — принятое правило, куцость подсвечивается. «Рассмотренные альтернативы» остаются подсказкой даже у ACCEPTED: решения без развилки бывают, и требовать выдуманный второй вариант значит поощрять выдумку.
- **Advisory, никогда не блокирует.** Сохранить можно всегда: мусорное значение хуже честного пропуска — оно неотличимо от настоящего.

## Новостная лента

- **Δ считает уникальные элементы, а не события.** Задача, попавшая в ленту и появлением, и закрытием, — две строки, но один элемент; сумма событий завышала итог.
- **Виды события — иконками** (появилось · изменено · закрыто · релиз), и разбивка выведена в заголовок дня и в группы по проектам, а не только в группировке по типам.
- **ADR и решения несут свой проект** (ADRPROJ-01). Раньше ADR-строка приходила без проекта вовсе и оседала в «без проекта»; то же дочинено для события «изменено».

## Спринты в интерфейсе

- **Авто-статус спринта из задач** — спринт больше не висит в `planned`, когда работа по нему уже идёт.
- **Компактная строка спринта** и раскладка задач по статусам во всех строках списка.
- **Отдельная палитра цветов статусов** (`--st-*`): цвет берётся из палитры авторитетно, словарь отвечает только за иконку.

## Релизы

- **Авто-`current` при создании** (ADR-LORE-025, OP-04): новый релиз сам становится текущим, прошлый снимается — без ручного шага, который забывался.
- Вердикт полноты релиза теперь приходит и на `update`/`unlink`, а не только на создании и линковке. На снятии связей он нужнее всего: именно там релиз становится неполным.

## Исправления

- **UC доходит до `shipped`.** Статус задачи читался прямо с вершины `KnowTask`, где такого свойства в схеме нет, — счётчик закрытых задач всегда был нулём, и ни один сценарий не достигал выпуска.
- **`bragi_link rel=rubric` действительно снимает рубрику.** Возвращал `ok:true`, а ребро оставалось: у эндпоинта не было параметра `action` вовсе.
- **Кириллические расширения UC не штрафуются.** Ссылки вида «2а», «3б» не распознавались (шаблон покрывал только латиницу), и корректно оформленный сценарий терял баллы.
- **`gain_delivered_not_claimed` не всплывает поверх невыполненных обязательств** — находка помечалась существенной вопреки собственному контракту.
- **Линтер читает поля из модели, а не из головы** (`D-2026-LORE-QUALITY-NO-PHANTOM-CHECKS`): у решения статус живёт в `status_raw`, у спеки поля статуса нет вовсе, у вехи — `label`/`date_display`. Проверка на несуществующее поле краснеет всегда и на всех, и от такого вердикта перестают читать весь.
- **MCP-гигиена:** `qg_run_log` обёрнут в try/catch как остальные write-инструменты; `spec_link` получил zod-дефолты, а не только обещание в описании.

## Данные

- **Бэкфилл проектов у ADR: 103 → 191 из 191.** Связь с проектом выводилась через компонент и подтверждалась вторым независимым признаком; неоднозначные случаи не угадывались, а решались владельцем. На будущее случай закрыт проверкой линтера.
