# v1.4.0 — мобильный канал, доверие к данным реестра, agent-full заводит проекты

Минорный релиз. Три новых куска функциональности (канал miniLORE, MT-09/MT-11 строгий разбор входа и парность ролей, VD-03 подсветка расхождения версий), пять находок о том, что реестр показывал не то, что было в данных, и завершение открытого сегодня хвоста — agent-full теперь может заводить проекты сам, а не упираться в гейт, непроходимый ни для кого.

## Багфиксы, которые реально ломали работу

- **Промоушн-PR не привязывался к релизу, а `release_unlink` врал про 0 снятых рёбер (CIM-03).** Автолинк цеплял PR к текущему релизу по `is_current` независимо от базовой ветки — PR промоушна `develop→preprod` уезжал в релиз, к которому отношения не имел. PR с базой `preprod`/`main` теперь пропускает автолинк и получает объяснение вместо тихой неверной привязки. `release_unlink` при несовпавшем ребре теперь возвращает `ok:false` с текстом причины, а не `sprints_removed:0` молча.
- **Статус читался по слову, а не по значку — те же 27 закрытых спринтов, что не распознавались в miniLORE (AL-117).** `classifyStatus` и срез `task_done_dates` искали подстроку `DONE` вместо разбора значка-маркера — выровнено на уже проверенный icon-first паттерн. Заодно найдено: `SPRINT_AUTH_CUTOVER` несёт дату завершения, совпадающую с плановой датой (похоже на подстановку при простановке статуса) — данные не тронуты, добавлена проверка на будущее (AL-118).
- **Проекты без единого текущего релиза — реестр не замечал (AL-116).** Найдено miniLORE: один проект застрял на релизе четырёхмесячной давности при сотне релизов между, другой нёс два «текущих» одновременно. Оба исправлены, добавлена проверка `release_single_current` в самопроверку корпуса.
- **«Подключения» описывали канал неверно.** Канал — не «один на рабочую папку», а дочерний процесс конкретной сессии; адресация была по имени проекта, из-за чего при двух диалогах в одном проекте сообщение уходило не туда молча. Переписано на адресацию по `sessionId`.
- **QG-аналитика — иконка «Нарушения open» не рисовалась.** Слаг не входит в офлайн-набор иконок, сетевого фолбэка нет — молчаливая пустота. Найдено внешней командой при переносе иконок LORE в мобильное приложение.

## Новое

- **Канал miniLORE.** Вкладка «Подключения» (раздел «Основа») — рецепт сведения консоли и мобильного приложения к одному диалогу, с двумя оговорками, найденными на практике. Админка — «Быстрые команды»: команды на каждый день одним кликом в буфер.
- **MT-09 — строгий разбор входа MCP.** Незнакомый параметр инструмента теперь `400` с именем и списком принятых ключей, а не тихо отброшенный. Найдено на практике: девять вызовов с опечаткой в имени параметра прошли `ok:true`, а два сценария остались без primary-актора. Плюс проверка «у сценария ровно один primary» в самопроверке корпуса.
- **MT-11 — ребро «роль ↔ агент».** Новый тип ребра `FILLS_ROLE`, запись через `actor_link(rel="fills_role")`, проверка совпадения работ пары (разность в обе стороны, а не булев вердикт) в самопроверке.
- **VD-03 — реестр технологий подсвечивает расхождение версий сам.** Раньше расхождения версий одной технологии между компонентами находились только глазами. Заголовок колонки красится по силе расхождения (мажор/минор/патч), расходящаяся ячейка получает рамку; версии без ведущей цифры («не закреплён») не путаются с числовым расхождением.
- **AL-119 — `task_uid` в `task_done_dates`.** По измерению miniLORE 12% значений `task_id` принадлежат больше чем одной задаче (короткие типовые коды вроде `T-01` — до 74 разных задач); джойн по одному `task_id` подписывал закрытую задачу чужим названием.
- **AL-84 — agent-full заводит проекты, в админке кнопка и попап.** Гейт `/lore/project` был непроходим на практике ни для кого: ни один из семи агентных профилей не писал туда, а у человека не было ни UI-кнопки создания, ни отдельной проверенной superadmin-учётки — только правка уже существующих строк. Открыт agent-full; человеческий порог не понижен (по-прежнему нужна именно роль superadmin). В админ-панели — кнопка «+ Добавить проект», карточка редактирования переехала в модальное окно.

## Мобильный UX — расширение подтверждённого приёма

Пилот document-level scroll (снятие автоскрытия мобильного браузерного chrome) был подтверждён живым тестом на паспорте спринта — распространён на все master-detail экраны (ADR, компоненты, спеки, quality gates). `StatusPicker` на строке задачи сжат отдельным ultra-compact тиром поверх уже существующего compact-режима.

## Известное открытое

- **Человеческий путь в `/lore/project` всё ещё требует именно роль `superadmin`**, не обычный `admin` — кнопка в админке есть, но сработает только у аккаунта с этой ролью. Пока единственный проверенный путь — agent-full.
- **MT-11**: сами семь пар «агент ↔ роль» не заведены — `ACT-LORE-TESTER` не существует как отдельный актор, `ACT-LORE-AGENT-SESSION` намеренно без пары. Решение по неоднозначным профилям — за владельцем/архитектором.
- **AL-106** (видимость акторов-агентов при включённом `lore.scope.enforce`) остаётся за владельцем.
