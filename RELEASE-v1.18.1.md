# LORE v1.18.1

Первая догонка 1.18. Исправлены три падения проверки релиза 1.18.0. У каждого агента теперь своя учётка MCP с ролью не выше главной роли его harness. MCP поднят на проде как сервис хоста. Основной адрес LORE переключается на новый интерфейс v2.

## Исправления

- **Дату в план спринта можно записать и у спринта без статуса** (SPRINT_LORE_MODEL_DOCS_TIDY/MDL-06, #1724). Повод: на базе 1.18 такая запись падала с ошибкой 400: при переводе запроса на новые имена полей значение статуса терялось. Теперь перед отправкой в базу каждый параметр запроса проверяется: он всегда передаётся, даже пустой. Правило общее для всех записей истории, а не только для плана спринта. Ценность: запись в план не падает из-за пустого поля, а такие ошибки больше не возникнут в других записях.
- **Флаги в модели описаны как флаги** (SPRINT_LORE_MODEL_DOCS_TIDY/MDL-06, #1724). Повод: «текущий релиз» и «закрытый проект» были описаны в модели строками, и каждая запись флага давала предупреждение «не текст». Теперь это вид bool. Новая проверка следит, чтобы поле, которое база хранит флагом, и в модели было флагом. Ценность: предупреждения о неверном виде значения снова означают настоящую ошибку.
- **У модели есть номер версии** (SPRINT_LORE_MODEL_DOCS_TIDY/MDL-06, #1724). Повод: версия схемы показывалась хэшем вроде `model:d7e16a827891d5e0`, и по нему нельзя понять, какая модель новее. Теперь `/lore/version` отвечает `model:1`, а хэш вынесен в отдельное поле. Любая правка модели, меняющая схему, обязана поднять номер, иначе проверка не проходит. На уже перенесённой базе номер 1 дописывается при старте, данные не меняются. Ценность: по номеру сразу видно, какая модель стоит.

## Учётки агентов в MCP

- **Учётка — на harness, роли — по старшинству** (SPRINT_LORE_OWN_HOST/OH-MCP-HOSTED-SWITCH, #1725, ADR-LORE-058). Повод: все сессии и подагенты работали под одной полной учёткой, и действие младшей роли записывалось как действие полной роли. Теперь у каждого harness одна главная учётка: `lore-mcp-<роль>` у Claude Code, `lore-mcp-<роль>_<harness>` у остальных. Порядок ролей задан в модели: full > architect > pm > product-analyst / analyst / developer / marketer > tester. Учётку с ролью выше главной для harness выпустить нельзя, сервер отказывает до похода в Keycloak. Ценность: в журнале видно, какая роль на самом деле сделала действие, а младший агент не получает прав старшего.
- **MCP сам называет роли для подагентов** (SPRINT_LORE_OWN_HOST/OH-MCP-HOSTED-SWITCH, #1725). Повод: агент не знал, под какой ролью запускать подагента. Теперь при старте MCP перечисляет роли не выше своей учётки и напоминает правило: подагент младшей роли работает под своей учёткой (переменная `LORE_MCP_SECRET_VAR` — имя ключа его секрета, #1724). Ценность: подагенты получают ровно те права, которые нужны.
- **Установщик спрашивает про свой Keycloak** (SPRINT_LORE_OWN_HOST/OH-MCP-HOSTED-SWITCH, #1725). Повод: план области Keycloak заводил учётки MCP без второго маппера, и такая учётка у чужой установки могла только читать. Теперь план заводит учётки по ролям с обоими мапперами и ролью агента. Уже установленную область он доводит, ничего не удаляя. Если у установки свои клиенты и секреты, установщик ничего не заводит, а только проверяет, что по ним выдаётся токен с нужной ролью. Ценность: MCP чужой установки пишет, а не только читает, и установщик не лезет в чужой Keycloak без спроса.

## Прод и адреса

- **MCP на проде — сервис хоста LORE** (SPRINT_UXR_S8_SWITCH/S8-02, #1723). Повод: в 1.18.0 сервис MCP был собран, но на прод не выкатывался, и `/mcp` отвечал ошибкой 502. Теперь MCP выкатывается вместе с бэкендом той же сборкой, и после выкатки проверяется, что `/mcp` на обоих адресах отвечает входом. Ценность: агенты подключаются к MCP по адресу LORE, без локальной сборки на каждой машине.
- **Основной адрес LORE — интерфейс v2** (SPRINT_UXR_S8_SWITCH/S8-02, #1723). Повод: v2 обращался к бэкенду через публичный адрес. Когда основной адрес переключили на v2, запросы пошли по кругу, и переключение пришлось откатить. Теперь v2 ходит к бэкенду напрямую, а выкатка отказывает до запуска, если адрес снова указывает на публичное имя. Ценность: lore.odal открывает v2, прежний адрес new.lore.odal продолжает работать.

## Модель и клиенты

- **Контракт экрана-списка в модели** (SPRINT_LORE_MODEL_AS_CONFIG/MC-09, #1700). Повод: мобильный клиент собирал списки по своим догадкам о срезах и полях. Теперь у каждого из 26 типов в модели описан список: какой срез, какое поле — код, заголовок, статус, группировка, нужен ли выбор проекта. Ценность: клиенты строят списки по модели LORE, а не по копии в своём коде.
- **Сводка медленных запросов** (SPRINT_LORE_OWN_HOST/OH-SLOW-QUERY-LOG, #1716). Повод: при жалобе «тормозит» не было видно, какие запросы к базе дороже всего. Теперь сервер собирает топ шаблонов запросов по суммарному времени. Ценность: оптимизировать можно то, что на самом деле занимает время.
- **Проверка «поле есть в схеме или в модели»** (SPRINT_LORE_MODEL_DOCS_TIDY/MDL-05, #1717). Повод: срез мог читать свойство, которого нет ни в схеме, ни в модели, и молча получать пусто. Теперь такая ошибка не проходит сборку. Ценность: пустые колонки из-за опечатки в имени поля не доходят до пользователя.
