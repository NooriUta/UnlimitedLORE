# v1.5.0 — след агентских сессий в графе, лента новостей, целостность релиз↔проект

Минорный релиз. Крупная связка из 18 изменений поверх v1.4.0: журнал агентских сессий и их саморегистрация, новостная лента LORE (бэкенд + экран в Forseti), несколько починок целостности данных (release_mv, ребро релиз→проект, пересоздание FT-индексов) и наблюдаемость CI.

## Агентские сессии — теперь наблюдаемы

- **Журнал сессий агентов (`KnowAgentSession`).** Действия агента получают точку привязки в графе: `machine_id`/`session_id` как устойчивые идентификаторы, вершина сессии, слайс `agent_sessions`.
- **Саморегистрация сессии при старте.** Сессия сама заводит запись в `KnowAgentSession` в момент старта — журнал не зависит от того, вспомнил ли кто-то зарегистрировать сессию вручную.
- **Журнал проектных ролей (`KnowProjectRoleEvent`, +миграция V27).** Выдача/снятие/изменение проектной роли пишется append-событием (кто, кому, какой проект, какое действие) — best-effort, сбой журналирования не роняет само изменение роли. Слайс `project_role_events`.

## Новостная лента LORE

- **`GET /lore/news`** — единый эндпоинт ленты новостей поверх существующих слайсов (порт из gateway miniLORE): новые слайсы `timeline_specs` и `adr_history_all`, параметры `since`/`before`/`limit`, устойчивый разбор трёх форм дат.
- **Экран «Новости» в Forseti** — лента выведена в веб-UI LORE (глава «Управление»), не отложена в бэкенд: `LoreNewsFeed` на токенах `var(--fs-*)`, роутинг на паспорта сущностей.

## Целостность данных

- **`release_mv` больше не двойит `release_uid`** и отказывается работать на неоднозначном id вместо тихой порчи (AL-111).
- **Ребро релиз→проект (PS-20, +миграция V26).** Связь релиза с проектом восстанавливается на создании/правке/переносе релиза; бэкфилл существующих рёбер миграцией.
- **Пересоздание FT-индексов (миграция V28).** На ArcadeDB 26.8.1 массовый `REBUILD INDEX` терял имена части полнотекстовых индексов — миграция пересоздаёт их через DROP+CREATE, поиск и BM25-ранжирование восстановлены.

## Устойчивость и CI

- **TTL кэша секретов (DBR-02)** — кэш секретов больше не держит устаревшее значение бессрочно.
- **Read-RBAC для Forgejo-операций (FJ-10).**
- **Слайс `open_tasks` (SE-01)** — с фильтрами по классу работы/спринту/проекту/компоненту.
- **Наблюдаемый откат docker registry-mirror (CIM-02).** Мёртвое зеркало базовых образов больше не немой отказ: проба перед сборкой пишет в лог состояние (`notice`/`warning`), движок 29.x сам откатывается на upstream.
