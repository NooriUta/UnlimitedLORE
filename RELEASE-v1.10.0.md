# v1.10.0 — роли задач живут в рёбрах, поля сняты

## Роли задачи ребром + норма ответов записи

### Зачем

Роли на задаче жили свободными полями `author/executor/reviewer_agent`. Замер прода 30.08.2026: **4114 заполненных значений, 73 различных написания при десяти заявленных личностях**. В поле «кто» стояли имена сессий, названия проектов и проза — ответы на другой вопрос.

Следствие не косметическое: гейт самоприёмки сравнивает строки, поэтому `owner` и `omiloreadmin` для него разные люди, и запрет обходится сменой написания.

### Схема

Миграции 35 и 36. Ребро `ROLE_HELD_BY`: роль, профиль, модель, вердикт, отзыв, пара `valid_from/valid_to`. Добор из полей только ДОБАВЛЯЕТ — поля остаются нетронутыми, пока обе правды не сойдутся; снятие полей отдельным шагом и последним.

Профиль и модель — атрибуты ДЕЙСТВИЯ, а не личности: агент мультиролевой, и на вершине они дали бы «последнее значение выигрывает» с потерей истории.

### Запись

- незаявленная личность — отказ **со списком кандидатов**, выведенным из графа;
- пустой список — отдельный ответ: в проекте нет ни одной роли, чинится в админке;
- тот же держатель — `unchanged`, не ошибка и не работа;
- смена — `updated` с именем прежнего, старое ребро **закрывается, а не стирается**;
- вердикт только у `reviewer`: у `handoff` его нет и быть не может — он ничего не оценивал;
- **агент не создаёт задачу без автора и исполнителя** — отказ, а не запись с пропуском.

### Форма

Список личностей вместо словаря ролей, приходит тем же методом, которым бэкенд проверяет запись. Значение вне списка не исчезает — показывается с пометкой «не заявлен». Пополнение словаря набранным текстом убрано: оно размножало написания.

### Норма ответов (ADR-LORE-043)

`outcome` называет произошедшее: `created`, `updated`, `unchanged`, `deleted`, `noop` с причиной. Исход выводится из ПРОБЫ ДО записи, а не из результата `CREATE EDGE`: тот доказывает отсутствие ошибки, но не факт записи. Покрыты все пути связывания в графе — ADR, решения, доки, вехи, продуктовый слой, Bragi, пакетная смена статуса. Keycloak исключён решением владельца.

Вердикт полноты сократился до «x из y» и списка только непройденного.

### Два дефекта чтения

Срез решений отдавал ровно 300 строк, самая поздняя дата — 31 июля: весь август был невидим без признака обрезки. Карточка решения не отдавала ни проекта, ни компонентов — принадлежность решения проекту нельзя было прочитать ничем.

Потолки у списочных срезов сняты полностью (решение владельца). Замер показал, что двое были на исходе: `specs` — 396 из 400, `docs` — 196 из 200.

### Проверка

Полный набор зелёный, включая живые тесты на настоящей базе: проводка ролей (10 проверок, рёбра читаются обратно из графа) и исходы связывания (6 проверок).


## Почему файл появился после тега

Тег v1.10.0 поставлен 31.08.2026 без этого файла: публикация `lore-release.yml` упала на шаге «нет RELEASE-v1.10.0.md» (задание 14749), релиза в Forgejo не было до 11.09.2026. Текст — из записи release:v1.10.0 в LORE, где он лежал с даты релиза; сюда перенесён дословно, публикация — ручным перезапуском workflow по тегу.
