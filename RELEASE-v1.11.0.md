# v1.11.0 — продукт получил дорожную карту, поиск по коду записи починен

Двадцать шесть содержательных коммитов, PR #601–#635. Два больших направления и десять тихих дефектов, каждый из которых отвечал успехом.

## Продуктовый слой заработал целиком

Продукты есть в справочнике, у вехи появился продукт, у продукта — карта.

**Тринадцать продуктов сидом.** Тип справочника был недостижим с обеих сторон: агенту `dict_set` отвечает 403 (словари правит человек — правило верное), а человеку вкладка «Справочники» строит список типов из **уже существующих** строк, поэтому пустой `dict_type='product'` в интерфейсе не появлялся вовсе. Обе половины по отдельности разумны, вместе давали запертую дверь.

**Дорожная карта принадлежит продукту**, а не git-проекту. Проект остаётся границей **прав** — аналог тенанта.

Почему не репозиторий — измерено, а не решено вкусом: тег `v1.0.23` висит под **двумя** проектами; монорепо держит **267** спринтов на десяток продуктов; UDWE размазан на **шесть** слугов; **17** спринтов сидят сразу в двух проектах. Продукт переживает переезд кода, репозиторий — нет.

Появились: ребро `TARGETS_PRODUCT` (оба конца проверяются до записи), срезы `roadmap` и `roadmap_unplanned` (второй отвечает на «что забыли поставить в план» — такого вопроса раньше задать было нельзя), продукт как **требование** в линтере полноты вехи, инструменты `milestone_link` и `milestone_sprints`.

## Поиск: попадание по коду записи роняло ВСЮ ветку

Самый заметный снаружи дефект релиза. Ранг строки читался так:

```java
((Number) r.getOrDefault("score", 1.0)).doubleValue()
```

`getOrDefault` подставляет умолчание, только когда ключа **нет**. Ключ есть всегда — ветка кладёт `$score` прямо в SELECT, — а вот ЗНАЧЕНИЕ приходит `null` у каждой строки, которую нашла вторая половина условия `id ILIKE :idlike OR SEARCH_INDEX(...)`. То есть у любого попадания **по коду записи**, когда текст запроса в полнотекст не попал.

NPE вылетал не в строке, а в обходе ветки, и внешний `catch` записывал ветку целиком в `warnings` — со всеми её находками. Наружу это читалось как «такой записи нет».

Замерено на боевом стенде до и после:

| | `search q="DBR-09"` |
|---|---|
| до | `hits: []`, `warnings: [Cannot invoke "Number.doubleValue()" … is null]` |
| после | 8 находок, `warnings: []`, с ранжированием и сниппетами |

Положительный контроль отдельно: запрос `RM-P17` — код записи, существующий **только** как идентификатор, в полнотекст такого слова не попадало. Находится, значит работает именно тот путь, который раньше ронял ветку.

## Лента новостей: правки решений пропадали три месяца

Правки решений **не попадали в ленту с 14 июня** — источника события не существовало. Событие теперь несёт **все** свои принадлежности списком, а не первую попавшуюся. У решения появился проект при записи, и гейт наконец его считает.

## Десять дефектов, каждый отвечал успехом

| дефект | цена |
|---|---|
| `$score = null` у попадания по коду | ветка поиска исчезала целиком |
| вердикт FT-индекса, взятый на пустом типе, = «пригоден» | кэш на 10 минут; страховка сканом не срабатывала |
| `@ConfigProperty(defaultValue = "")` с типом `String` | приложение не стартовало вовсе |
| рёбра продуктовой оси только в bootstrap-DDL | вся ось после выката отвечала бы ошибкой на каждую запись |
| второй родитель у продукта, цикл в дереве | обход показал бы один случайный из двух |
| одна дата в **четырёх** видах у `KnowTaskHist` | сортировка и окна по датам врали молча |
| срез релизов резал **середину** окна | счёт «за N дней» занижен, отличить не от чего |
| проектный параметр слайсов вёлся в двух местах | ручной список отстал впятеро |
| слайс `git_projects` объявлен **дважды** | наружу шла форма без `is_private` |
| слияние цепляло PR к **уже выпущенному** релизу | связи уезжали в чужой релиз |

## Умолчание «NooriUta/AIDA» снято с обеих сторон

Релиз адресуется парой `release_uid = «репозиторий#версия»`, и один номер версии живёт в разных репозиториях — на 23.08.2026 таких пересечений **тринадцать**. Значит неверный репозиторий это не «уехало не туда», а запись в **чужой** релиз.

Сервер: `projectOf` больше не угадывает, возвращает `null`, вызывающий отвечает 400 с внятным текстом. Escape-hatch — настройка `lore.release.default-project`, пустая по умолчанию.

Экран: в паспорте спринта ссылка на релиз и PR не строится, когда репозиторий неизвестен или их несколько; вместо ложной ссылки — приглушённый значок с подсказкой, почему её нет. Номер PR при этом виден: пропадает ссылка, а не факт.

## Права и роли

Роли подагентов — белыми списками, со сторожем от расхождения с матрицей. Роль агента больше не расширяется молча ни на MCP, ни на бэкенде. В списках задач видно имя держателя, а не служебный идентификатор.

## Диагностика

Сводка упавших тестов в CI печатает сообщение **целиком**, а не первую строку исключения: инструмент диагностики, результат которого нельзя прочитать, диагностикой не является.

Добавлен сторож `ConfigEmptyDefaultDeclaredTest` — статическая сверка «у каждого `defaultValue = ""` ключ объявлен в `application.properties`». Проверен положительным контролем: при снятом объявлении краснеет и называет ключ.

## Совместимость

Шаги миграции **V40–V46**. Раннер в режиме upgrade требует бэкап: не снялся — миграция не стартует. V41 идемпотентен и не трогает непонятную форму — считает отдельно и пишет в лог с примером. V46 при отсутствии личности в графе **прерывается**, а не отчитывается «создано 0» (см. раздел про роли ниже).

Ключей в ответах не убрано и не переименовано. У `milestones` добавилось поле `products`.

## Чего в релизе нет

**Единого представления времени по всему корпусу.** `KnowSprintHist` и `KnowDictEntryHist` остаются DATETIME, остальные десять типов — текст ISO-8601 UTC. Внутри себя обе половины согласованы; сведение меняет выдачу `sprint_starts`, на которой висит аналитика. Развилка с обеими ценами и свежим замером — `SPRINT_LORE_ROADMAP_PER_PROJECT/RM-P13`.

**Включения `lore.scope.enforce`.** Ось прав определена (`D-2026-LORE-RBAC-BY-PROJECT`: права по проекту, продукт — витрина), но под скоупом сегодня 9 слайсов из 135. Включить флаг сейчас значило бы объявить изоляцию, накрыв ею 6,7 % выдачи, — это хуже честного «изоляции нет». Пошаговый план — `SPRINT_LORE_ROADMAP_PER_PROJECT/RM-P9`.

## Роли: 123 значения из примечаний стали рёбрами

Работа соседней сессии (AO-05, решение владелицы 31.08.2026 «все агент full, атрибуты за тобой»), доехавшая в `develop` к моменту выпуска. Вписана сюда, а не отложена: релиз обязан называть **всё**, что в нём уехало, иначе через неделю его не отличить от любой другой сборки.

Шаг миграции **V46** `role_edge_origin` добавляет необязательный атрибут `ROLE_HELD_BY.origin`, куда **дословно** ложится строка из снятого поля (`rollout`, `minilore-app`, «claude-full + соседняя сессия»…) — без приведения к общему виду: группировать значения решили отдельно.

Java-часть шага разбирает блок V38 в открытом примечании задачи и ставит `ROLE_HELD_BY` на `AGENT-FULL`, если открытого ребра этой роли нет. Считаются **значения**, а не примечания — расхождение «124 против 123» шло именно отсюда: цитата метки в прозе за метку не считается. Примечания не чистятся, это след происхождения. Нет личности в графе при наличии блоков — шаг **прерывается**, а не отчитывается «создано 0».

Тесты: `DroppedRoleNoteTest` (5, чистый разбор), `DroppedRoleEdgesLiveDbTest` (3, живая БД: ребро с `origin` дословно, повтор ничего не добавляет, примечание на месте, метка в прозе ребра не даёт).
