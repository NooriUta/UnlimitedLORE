# Карточки методов для витрины МУНИНН

Загрузчик `ExpMethodCard` — карточек конкурентов и смежных работ, которые
показывает вкладка «Библио · Исследования» экрана RAG · Graph · Parse.

## Откуда это здесь

Перенесено из `rag-vs-parse/scripts/` **04.09.2026** по решению владельца.
Причина переноса, а не ссылки на соседний репозиторий: витрина `RAGVSDL`
теперь живёт на ci-server рядом с LORE, а исходный репозиторий рассчитан на
локальную ArcadeDB, которой больше нет.

Содержимое карточек и логика сборки перенесены **дословно**. Отличий три, все
намеренные:

1. **Подключение из окружения.** В оригинале адрес базы и пароль root были
   зашиты в исходник и лежали в git. Здесь их нет: `ARCADE_URL`, `ARCADE_DB`,
   `ARCADE_USER`, `ARCADE_PASSWORD`. Пароль не задан — выход с явным
   `BLOCKED`, а не молчаливый 401: 401 внутри цикла upsert выглядел бы как
   «карточки не записались», и причину искали бы в данных.
2. **`ensure_schema()`.** Ни один скрипт исходного репозитория не создаёт
   типы `ExpMethodCard` и `CARD_OF` — их заводили руками в консоли. На
   витрине, восстановленной из бэкапа старше карточек, это давало
   `Type with name 'ExpMethodCard' was not found`, а `INSERT` молча не
   проходил (`run()` глотает ошибку и возвращает `None`).
3. **Типы создаются БЕЗ `EXTENDS V`/`EXTENDS E`.** У всех существующих типов
   этой витрины `parentTypes` пуст. В тот же день привычка писать `EXTENDS E`
   уронила стенд LORE (`V43: Supertype 'E' not found`) — супертип берётся из
   фактической схемы базы, а не из привычки.

## Как запускать

```sh
export ARCADE_URL=http://localhost:2480      # рядом с базой
export ARCADE_PASSWORD=…                     # только из окружения
python3 cards_b1.py && python3 cards_b2.py && python3 cards_b3.py
python3 patch_temporal_cards.py              # см. ограничение ниже
python3 fix_methodcard_fanout.py
```

Порядок существен: `b1`→`b2`→`b3`, затем патчи в порядке их дат
(`patch_temporal_cards` 23.06, `fix_methodcard_fanout` 25.06).

Идемпотентно: `upsert` обновляет запись по `card_id`, а не заводит вторую.

## Два известных ограничения, и оба про ВОЗРАСТ витрины

Витрина восстановлена из бэкапа **13 июня**, а карточки собраны **23 июня**.
Между этими датами библиография пополнялась, и восстановленный снимок этого
пополнения не содержит.

- **`CARD_OF` 15, а не 25.** У десяти карточек нет своей записи в
  библиографии: `route_2024`, `reasoning_sql_2025`, `cot_dpo_sql_2025`,
  `think2sql_2025`, `reex_sql_2025`, `unjoin_2025`, `text2sql_flow_2025`,
  `judgesql_2025`, `evolsql_2025`, `diver_2026`. Ребро при этом НЕ создаётся
  молча — `CREATE EDGE … TO (SELECT …)` с пустой выборкой не падает. Сами
  карточки видны, не привязана только ссылка.
- **`patch_temporal_cards` падает** на `ExpTopic` с `topic_id='topic:dkg_temporal'`:
  темы в снимке нет, она заведена позже.

Масштаб отставания измерен: в восстановленной витрине **56** записей
`ExpReference`, а `materialize_tree.py` (24.06) печатает «было 131 +6 = 137».
То есть снимок отстаёт примерно на **80** ссылок. Это не потеря при переезде —
эти данные просто ни разу не попали в бэкап.
